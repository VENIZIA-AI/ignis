`@venizia/ignis-atlas` is the MCP server for IGNIS: one process answers "what does the manual
say" over three corpora - the wiki, the changelogs, and the agent-facing knowledge bundle - with a
citation on every answer. It replaces two retired servers, `ignis-docs-mcp`
(`docs/wiki/mcp-server`) and `ignis-knowledge` (`.agents/knowledge-tools`'s `mcp.ts`, now deleted);
see the [changelog](/changelogs/2026-09-06-ignis-atlas).

Position in the chain: `helpers -> atlas`, a leaf like `boot` - nothing in the framework depends on
it. Runtime dependencies: `@venizia/ignis-helpers`, `zod` and `@hono/zod-openapi` - the last one because the helpers root barrel (the only entry that exports `LoggerFactory`) needs it; helpers lists it only as a peer dependency, and atlas, a leaf with nothing downstream to satisfy that peer from, pins it directly. `scripts/atlas-pack-smoke.ts` proves the packed tarball starts in an empty directory, and the release workflow runs it for `atlas`. Single CJS build, no ESM pass -
the package ships one CLI, not an importable runtime surface. Its own `index.ts` re-exports
`common` only (constants and types); `buildServer` and the tools are reached through the CLI, not
imported. Bin `ignis-atlas -> dist/cjs/cli.js` with a `bun` shebang. Bun-only: the index is
`bun:sqlite` FTS5, so a Node consumer cannot run the server.

## Modes

Two modes share one engine, chosen by what `--root` (default `process.cwd()`) looks like.

| Mode | Trigger | Roots | Corpora shipped |
|---|---|---|---|
| repo | `--root` has `docs/wiki/content` and `.agents/knowledge` | the live tree | wiki, changelog, knowledge |
| snapshot | otherwise, when the package directory has `dist/corpus` | the packaged snapshot | wiki, changelog (no knowledge) |

A checkout is recognised by all three corpus directories AND a root `package.json` named
`@venizia/ignis-workspace`. The directories alone are a layout consumers copy: one carried both and
no `changelogs`, and the server died on `ENOENT` before its first JSON-RPC line instead of serving
its own snapshot.

`src/cli/modes.ts`'s `findPackageDirectory` walks up from `__dirname` to the directory whose
`package.json` names `@venizia/ignis-atlas` - never a fixed number of `..` segments, since a
source run starts at `src/` and the built CLI starts at `dist/cjs/`. A root that satisfies neither
mode throws `ModeUsageError`, caught by `cli.ts` and printed as usage (exit 2).

## The index

One FTS5 row per H2/H3 section, chunked from every `.md` file in each corpus root (a fenced code
block is never split). Ranking is `bm25(...) * authority`: title, heading path, body and symbols
carry weights (title highest), frontmatter `description`/`type`/`tags` are indexed too under
`metadata` - deliberately excluding `title`, which already leads every chunk's `headingPath` and
would otherwise double-count. Authority discounts `log.md` (history) and changelog entries below a
canonical page, so a page that only mentions a term does not outrank the page that is about it.
Query planning is AND-first: every term must match, and only when that yields too few rows does a
second, OR pass run and append. A result page keeps at most 2 chunks per document, backfilled from
the next distinct document in rank order - `limit` hits at that stage, before the reply-size
budget below can still trim the page further.

Every chunk id is a citation: `wiki:<path>#<anchor>`, `changelog:<date>-<slug>#<anchor>`,
`okf:<path>#<anchor>`. `get` reads a chunk's full body by that id.

## Symbols

The `symbol` tool answers from `.agents/knowledge/reference/symbols.json`, generated by
`scripts/atlas-symbols.ts` from every package's built `.d.ts` - the same surface
`scripts/public-surface.ts` snapshots. The prose in this bundle is never the source of truth for a
signature; the built declaration is.

- **`file` and `line` name the source, not `dist`.** The generator decodes the `.d.ts.map` beside
  each declaration, so a hit lands on `packages/<name>/src/...`. Without a map it falls back to
  path arithmetic and keeps the `.d.ts` line; it never guesses a source position.
- **A re-exported third-party declaration is marked `external: true`.** Its `file` is a
  `node_modules` path, an install detail, not repository source - 26 records today.
- **An alias points at what it aliases.** `export { BaseRelationalEntity as BaseEntity }` records
  `BaseEntity` on `BaseRelationalEntity`'s line, so that line does not spell the alias out.
- **Drift is a build failure.** `make symbols-check` runs inside `make build-all` beside
  `surface-check`; run `make symbols-gen` after an intentional API change.
- **The table is generated from `dist`, so a stale `dist` makes it stale.** Editing `src` without
  rebuilding moves a declaration's line and the table does not follow.
- **The snapshot must carry it.** `packages/atlas/scripts/build.sh` copies the table into
  `dist/corpus/symbols.json` and fails when it is missing. A build with no table still starts; the
  tool answers `-32602 no symbol table in this build`.

## Releases

The `version` and `changes` tools answer from `.agents/knowledge/reference/releases.json`,
generated by `scripts/atlas-releases.ts` from `git log` and the changelog directory. It carries two
things: every `chore(<package>): release v<version>` commit, keyed by the directory name under
`packages/`, and every dated changelog file with the packages it names.

- **Commit position decides a version window; dates decide a date window.** Every release and
  every changelog carries `order`, its position in first-parent history, so two releases of one day
  are separable. `changes` takes `fromOrder < order <= toOrder` for two versions and
  `fromDate < date <= toDate` for two dates, the lower bound open, the upper closed. An entry the
  table has no position for falls back to its date.
- **A changelog with no package resolves to none.** Package inference tries a `packages:`
  frontmatter list, a Details table's `Package` column, `@venizia/ignis...` mentions, then
  `packages/<dir>` paths; the first rule that hits wins. A bare word must name a directory this
  repository has released, so a `Package` column carrying prose never invents a package. A file no
  rule answers for keeps an empty `packages` - 9 of 118 files today. The generator never guesses.
- **A file with no `YYYY-MM-DD` prefix is not an entry.** `template.md` and
  `planned-schema-migrator.md` have no date, so they can never fall inside a window and are left
  out rather than carried with an invented one.
- **`version` never calls the registry.** `installed` is resolved from the caller's
  `node_modules`, falling back to the declared spec only when that spec is one exact version; a
  range reads `null` and is never counted as behind. `snapshot` is what this table knows, which
  includes retired packages (`core`, `docs-mcp`) that still have release commits in the history.
- **Drift is a build failure.** `make releases-check` runs inside `make build-all` beside
  `symbols-check`; run `make releases-gen` after a release commit or a new changelog page.
- **The snapshot must carry it.** `packages/atlas/scripts/build.sh` copies the table into
  `dist/corpus/releases.json` and fails when it is missing. A build with no table still starts;
  both tools answer `-32602 no release table in this build`.

- **The default window skips a same-day predecessor.** Several releases of one package on one
  day are normal here, so `changes({ package })` walks back to the newest version of an earlier day.
- **`version.snapshot` lists the packages that exist today**, from `livePackages` in the table;
  `changes` still reads a retired package history.

## Budgets

`search` replies stay under 2,000 characters, trimming trailing hits - never `total` - until it
fits. The response carries `returned` (hits actually in this reply) and `nextOffset` (absent when
nothing follows); page with `offset: nextOffset`, not `offset + limit`, so a page the budget
trimmed is never skipped. `get` pages a body at 8,000 characters by default (`maxChars` widens
this to 50,000), returning a base64 offset `cursor` for the next page. Neither tool returns a
whole file uncapped - the two servers this replaces both did; `ignis-knowledge` served one
87,709-character response for a single reference page.

## Freshness

Repo mode fingerprints its roots - file count, newest mtime, total bytes, one `Bun.Glob` walk per
root - before every tool call, and rebuilds the store when it moved. Snapshot mode never rebuilds:
the packaged corpus is immutable for the life of the process.

## Golden test

`src/__tests__/golden/queries.json` fixes a query set against the real repository corpus, with the
expected chunk in the top 3 and, where a past regression named a document that must not reappear, a
`rejectAnyOf` prefix. Every golden query must pass; a ranking change that drops one below the top 3
fails the build, not a human eyeballing a table.

## Constraints the code cannot show

- **Tool wrapping, not tool modification.** `buildServer` wraps `search`/`get` so every `call`
  re-resolves the store through `FreshnessGuard.getStore()`; the tool builders in `src/tools/`
  never know a guard exists.
- **The fingerprint cannot see a pure rename.** Identical bytes, identical mtime, only the path
  changed - nothing in the fingerprint reads the path itself, so the guard skips the rebuild.
- **`knowledge` is never shipped.** The npm snapshot packages `wiki` and `changelog` only - the
  bundle documents internal process, not something a consumer's agent should search.
- **Diagnostics are stderr-only.** A stdout discipline test asserts the process writes nothing but
  JSON-RPC frames to stdout during `initialize`, `tools/list` and one `search` - a stray
  `console.log` anywhere in the import graph breaks every client's framing, not just the visible
  one.

## Family checkouts

Repo mode is not IGNIS-only: `isRepositoryCheckout` accepts any root manifest named `@venizia/<family>-workspace` that keeps `docs/wiki`, its `changelogs` and `.agents/knowledge` at the IGNIS paths, and the server names itself `<family>-atlas`. ARDOR (`@venizia/ardor-workspace`) is the first sibling to run atlas this way. Snapshot mode always serves the IGNIS corpus under the package's own name.
