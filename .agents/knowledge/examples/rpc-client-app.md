`rpc-client-app` is the one non-server example: a small React 19 + TypeScript + Vite single-page
app. It depends on no `@venizia/ignis*` package at all, directly or transitively - its only tie to
the framework is the committed `src/api/schema.d.ts`, generated from
[`rpc-api-server`](/examples/rpc-api-server.md)'s running OpenAPI document. The coupling is a type
contract, not a package edge.

## What it demonstrates

- **Type-safe API integration** - `schema.d.ts` (generated by `openapi-typescript` from
  `http://localhost:3000/api/doc/openapi.json`) backs an `openapi-fetch` client wrapped by
  `openapi-react-query` into `$api`. `$api.useQuery("get", "/configurations")` knows the path, the
  body and the reply; a renamed route fails the build.
- **`src/api/client.ts`** adds the Bearer token to every request; `src/auth-form.tsx` signs up and
  signs in with `$api.useMutation`; `src/configurations.tsx` lists, creates and deletes with
  `$api.useQuery` / `$api.useMutation`; `src/app.tsx` keeps the token in `localStorage` and switches
  between the two screens.
- **No CORS** - the Vite dev server forwards `/api` to `http://localhost:3000`, so the browser never
  makes a cross-origin request.

## How to run it

Start [`rpc-api-server`](/examples/rpc-api-server.md) first, then:

```bash
bun install
bun run dev            # vite dev server, http://localhost:5173
bun run generate         # openapi-typescript http://localhost:3000/api/doc/openapi.json -o ./src/api/schema.d.ts
bun run build             # tsc -b, then vite build - fails where the client no longer matches
```

## Notable / non-obvious

- This example has no `bun run test` script and is not in `EXAMPLES_SMOKE` - only the server side of
  the pair gets a smoke test in CI.
- `bun run generate` needs the server running; regenerate after any change to
  `rpc-api-server`'s routes or schemas, or the build fails on the mismatch.
