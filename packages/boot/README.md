# @venizia/ignis-boot

Build-time tools for an IGNIS application: `ignis-artifacts` writes one static file that registers your decorated classes, and `ignis-build-info` stamps the build. Install it as a devDependency of the application.

## Install

```bash
bun add -d @venizia/ignis-boot typescript
```

`typescript` 5 or 6 is a required peer: the scanner reads your source with the TypeScript compiler API. Both binaries run under Bun (they carry a `bun` shebang).

## Register your classes

Decorate the classes you want registered:

```typescript
import { BaseService, service } from '@venizia/ignis';

@service()
export class PricingService extends BaseService {
  constructor() {
    super({ scope: PricingService.name });
  }
}
```

Add two scripts and run the first one:

```json
{
  "scripts": {
    "generate:artifacts": "ignis-artifacts generate --root src --out src/generated/artifacts.ts",
    "check:artifacts": "ignis-artifacts check --root src --out src/generated/artifacts.ts"
  }
}
```

`generate` writes plain static imports and one object:

```typescript
// AUTO-GENERATED by @venizia/ignis-boot - do not edit. Regenerate: ignis-artifacts generate --root src --out src/generated/artifacts.ts
import { PricingService } from '../services/pricing.service';

export const GeneratedArtifacts = {
  configurations: [],
  dataSources: [],
  components: [],
  repositories: [],
  services: [PricingService],
  controllers: [],
};
```

Hand that object to the application. The `registerArtifacts` boot step binds every class in it:

```typescript
import type { IApplicationConfigs } from '@venizia/ignis';
import { GeneratedArtifacts } from './generated/artifacts';

export const configs: IApplicationConfigs = {
  path: { base: '/api', isStrict: true },
  artifacts: GeneratedArtifacts,
};
```

Commit the generated file and never edit it by hand. Run `check:artifacts` where lint runs, so a stale index fails before it reaches CI.

The scanner reads source text and never imports a module. No decorator runs and no import side effect fires, so a datasource that opens a pool at import stays inert. Because the output is plain imports, `bun build --compile` sees every class; a compiled binary has no source tree to scan at run time.

## `ignis-artifacts`

```
ignis-artifacts <generate|check> [--root src] [--out src/generated/artifacts.ts] [--ignore a,b] [--export GeneratedArtifacts]
```

| Flag | Default | Meaning |
|---|---|---|
| `--root` | `src` | Directory to scan, recursively (`.ts` files, `.d.ts` skipped) |
| `--out` | `src/generated/artifacts.ts` | Output file; import paths are relative to it |
| `--ignore` | none | Comma-separated globs, relative to `--root`, added to the default list |
| `--export` | `GeneratedArtifacts` | Name of the exported constant |

The default ignore list always applies: `**/__tests__/**`, `**/*.test.ts`, `**/*.spec.ts`, `**/generated/**`. A decorated class hidden by one of your own `--ignore` patterns prints one `warning:` line on stderr.

| Command | Effect | Exit code |
|---|---|---|
| `generate` | Writes `--out` only when the content changed | `0` |
| `check` | Renders in memory and compares with `--out`, ignoring the header line | `0` fresh, `1` stale or missing |
| anything else | Prints the usage line | `2` |

### What gets emitted

A class lands in the index when all of these hold. The scanner logs a warning for a decorated class it skips.

- It is a named export (`export class` or `export { Name }`), not `export default`.
- It is not `abstract`.
- It carries exactly one of `@configuration`, `@component`, `@controller`, `@service`, `@repository` or `@datasource`, imported by name from `@venizia/ignis` or `@venizia/ignis-kernel` (aliases resolved). `@injectable({ type })` counts when `type` is a string literal or `ArtifactTypes.<NAME>`.

`@model` classes are recognized and never emitted - a repository registers its model. A decorator re-exported through your own wrapper module is not recognized. Two stereotypes on one class fail the scan.

The output is deterministic: imports sorted by path, names sorted within each field, empty fields kept, a field wider than 100 columns wrapped one name per line.

## `ignis-build-info`

A compiled binary or a Distroless image has no `.git` and no readable `package.json`, so `ignis-build-info` resolves the build stamp at build time and writes it as a static file.

```
ignis-build-info generate [--out src/_build_info.ts] [--root .] [--format ts|json] [--export BUILD_INFO]
```

| Flag | Default | Meaning |
|---|---|---|
| `--out` | `src/_build_info.ts` | Output file; rewritten on every run |
| `--root` | `.` | Where `package.json` is read and `git` runs |
| `--format` | `ts` | `ts` writes an `export const`; `json` writes the same record as JSON |
| `--export` | `BUILD_INFO` | Name of the exported constant in `ts` format |

Each field reads the environment first (first non-blank key wins), then its fallback. A field nothing resolves reads `unspecified`.

| Field | Environment keys, in order | Fallback |
|---|---|---|
| `service` | - | `package.json` `name` |
| `version` | `APP_ENV_BUILD_VERSION`, `APP_BUILD_VERSION`, `CI_COMMIT_TAG`, `GITHUB_REF_NAME` | `package.json` `version` |
| `commit` | `APP_ENV_BUILD_COMMIT_TAG`, `APP_BUILD_COMMIT`, `CI_COMMIT_SHA`, `GITHUB_SHA`, `COMMIT_SHA` | `git rev-parse --short=12 HEAD` |
| `branch` | `APP_BUILD_BRANCH`, `CI_COMMIT_REF_NAME`, `GITHUB_REF_NAME`, `BRANCH_NAME` | `git rev-parse --abbrev-ref HEAD` |
| `builtAt` | `APP_ENV_BUILD_DATE`, `APP_BUILD_DATE` | the time the generator ran |

Register the stamp once at the entry point. The health-check component's `/stats` route reports it:

```typescript
import { BuildInfoRegistry } from '@venizia/ignis-helpers/core';
import { BUILD_INFO } from './_build_info';

BuildInfoRegistry.set({ buildInfo: BUILD_INFO });
```

## Entry points

| Subpath | What it gives | Extra peers |
|---|---|---|
| `@venizia/ignis-boot` | Everything from the two subpaths below | `typescript` |
| `@venizia/ignis-boot/generator` | `generateArtifactIndex`, `checkArtifactIndex`, `ArtifactScanner`, `ArtifactIndexEmitter`, `ArtifactStereotypes`, `ArtifactTypes`, `ArtifactIndexFields` | `typescript` |
| `@venizia/ignis-boot/build-info` | `generateBuildInfo`, `BuildInfoResolver`, `BuildInfoEmitter`, `BuildInfoFormats`, `BuildInfoEnvironmentKeys` | none |

| Binary | File |
|---|---|
| `ignis-artifacts` | `dist/cjs/clis/artifacts.js` |
| `ignis-build-info` | `dist/cjs/clis/build-info.js` |

The package ships CommonJS and ESM builds. The programmatic API mirrors the CLI:

```typescript
import { checkArtifactIndex } from '@venizia/ignis-boot/generator';

const { isFresh } = checkArtifactIndex({ root: 'src', out: 'src/generated/artifacts.ts' });
```

## Where it sits

`dev-configs -> inversion -> {filter, helpers} -> {boot, kernel} -> connectors -> {core-worker, core-server} -> atlas`. Boot depends on `@venizia/ignis-helpers` only; no IGNIS package depends on boot, so the application declares it.

The generated index replaces the runtime booters IGNIS once took from LoopBack 4, which globbed the file system at startup.
