IGNIS 0.4.8 is a hardening and cleanup release. It lets a child model take its row scope from its parent, closes many request-side and helper-side gaps (hidden fields, raw search, default filters, body limits, storage paths, redaction, crypto options, JWT claims and JWKS urls), rebuilds the static-asset component and the CRUD and search controller factories, and gives the Redis and mail helpers safer defaults. It also replaces `any` with `unknown` or `never` across the public types, removes the `AnyType` and `AnyObject` aliases, trims the shared lint presets, and lets a datasource open on first use. Apps that configure JWT, the static-asset component, the controller factories, Redis helpers or mail queues, and code that read `any`-typed values, must edit them before they upgrade. Some defaults also changed (upload file count, Redis reconnects, outbound proxies, WebSocket and Socket.IO delivery, S3 virtual-hosted buckets, `where` nesting, lint padding), so read every Breaking item; `migration.yaml` gives a before and after for each breaking item. Run `bun run devz codemod --list` for the codemods that cover the mechanical renames; `env-get` and `any-aliases` handle the `applicationEnvironment.get` type arguments and the removed aliases.

## Breaking
- **ScopeWriteOperations is now ScopeOperations, and access.resolve receives the operation** `scope-operations` (`@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`): `settings.access.resolve` is called with `{ operation }` (`ScopeOperations.READ`, `CREATE`, `UPDATE` or `DELETE`), so a model can read wider than it writes. `ScopeWriteOperations` and `TScopeWriteOperation` are removed from the connectors; import `ScopeOperations` and `TScopeOperation` from `@venizia/ignis-kernel` or `@venizia/ignis`, and type a `mutation` or `operation` you pass to `applyScopeFilter`, `applyDefaultFilter` or `guardScopedWrite` as `TScopeOperation`. A soft delete now calls the protected `_update` directly, so an `updateById` or `updateBy` override no longer sees it. With `write.sharedRows: true`, an update or delete whose scope the guard cannot read (a range, a `like`, an `or` over two columns) is refused. A `resolve` that takes no parameter keeps working.
- **Model access settings are a union** `access-settings-union` (`@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`): `IModelSettings.access` and `getAccessSettings()` are `TModelAccessSettings`, a resolver or a `through`, so code that calls `access.resolve(...)` on model metadata must first rule out `through`. `guardScopedWrite` is `async` and takes an optional `transaction`; await it. `IRelationalQueryExecutor` gains `supportsRowLock`, and an `IRelationalQueryDialect` that does not extend the engine's filter builder must add `resolveThrough`, `toParentWhere` and `resolveAccessScope`. See `access-through`.
- **dev-configs no longer installs eslint-plugin-n and eslint-plugin-unicorn** `drop-eslint-plugin-n-unicorn` (`@venizia/dev-configs`): the install is 78 packages and 16 MB smaller. A config of your own that names `n/prefer-node-protocol` or `unicorn/switch-case-braces` fails with "Could not find plugin". Rename `unicorn/switch-case-braces` to `venizia/no-unbraced-case` and delete `n/prefer-node-protocol`; `oxlintConfigs` still checks the `node:` prefix, and `eslintConfigs` no longer does.
- **asyncStyleConfigs and reactAsyncStyleConfigs are removed** `remove-async-style-configs` (`@venizia/dev-configs`): `houseConfigs` now carries the four async style rules, and `reactHouseConfigs` also the two hook rules, so the lint config is `export default houseConfigs;`. Drop the import and the spread. A project that only spread `houseConfigs` now gets the async rules; run `bun run devz codemod async-style` for the fixable findings.
- **A second Typesense sort is an error** `typesense-single-sort` (`@venizia/ignis-connectors`): a `sort_by` in `engineParams` used to override `filter.order` silently; it now throws, as does an empty, unbalanced or over-long (more than three top-level entries) `sort_by`. Drop one of the two. The refusal for a tuning key given twice now names the query one as `query.<key>`, and `order: []` no longer sends `sort_by: ''`. See `typesense-sort-by`.
- **BunS3Helper.listObjects lists the top level by default** `bun-s3-list-objects-top-level` (`@venizia/ignis-helpers`): `useRecursive` defaults to `false`, as `DiskHelper` and the docs always said. A call that relied on the old `true` passes `useRecursive: true`.
- **authenticate requires a user id in the default any mode** `authenticate-requires-user-id` (`@venizia/ignis-kernel`, `@venizia/ignis`): a strategy that answers without a `userId` counts as failed in `any` mode too, as it already did in `all` mode; the next strategy is tried, and the request gets `401` when none identifies a user. A custom strategy returns the user id in its answer.
- **A caller's where cannot replace the default filter** `default-filter-not-replaceable` (`@venizia/ignis-connectors`, `@venizia/ignis`): a `where` on a field the model's default filter also sets is ANDed with it, so `where: { isDeleted: true }` no longer returns the soft-deleted rows. It applies to reads, counts, `updateBy`, `deleteBy` and the `scope.where` of an include. Server code that must see the hidden rows passes `options: { shouldSkipDefaultFilter: true }`, which drops the whole default filter; a request cannot send it.
- **A request cannot filter or sort on a hidden field, and a hidden field answers like a missing one** `hidden-field-filter-parity` (`@venizia/ignis-filter`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`): on the generated CRUD and search controllers, a `where`, `order` or include `scope` that names a hidden property answers `400`, with the same error as a column that does not exist, even next to other bad keys, and `findById` ignores a `where`. On a search controller each field of a comma-joined list (`facetBy`, `groupBy`, `queryBy`, the highlight lists, a `facetQuery` field and `vectorField`) is checked, and a wildcard in those lists is refused on a model with hidden fields. A Meilisearch `filter.order` entry on a field the collection does not declare, such as a distance sort, now answers `400`: send it through `mode: 'raw'`. Filter on a visible property, or do it in server code; repository methods are unchanged. A class that implements `IRelationalQueryDialect` must add `resolveInclusion`, and one that implements `ISearchQueryDialect` must add `includeNotSupportedError`.
- **A search controller refuses raw mode, multi-search and engineParams unless you list them** `search-raw-mode-closed` (`@venizia/ignis-connectors`, `@venizia/ignis`): `mode: 'raw'` and the multi-search route answer `400` on a generated search controller unless it sets `modes: { raw: { use: true } }` (a toggle like `routes`); a scoped controller cannot opt in. A request that carries `engineParams` (a `multi-search` entry too) answers `400` unless the controller names the knob in `query: { allow: { tuning: [...] } }`: camelCase names typed by the repository's datasource (`DefaultSearchRepository<TDoc, TypesenseDataSource>`; with no typed datasource nothing can be allowed), and the body's `engineParams` of `POST /search` is a strict object of exactly those names, so a wire spelling such as `num_typos` is a `400`. Parameters that select rows or fields or reorder them (`filter_by`, `include_fields`, `query_by`, `sort_by`, ...) can never be listed, and the factory throws when the list holds one. `SearchRawAccess.resolve` takes the toggle as `raw`. `repository.search(...)` and `dataSource.multiSearch()` in server code are unchanged.
- **AES and RSA never return their input on failure** `remove-aes-rsa-do-throw` (`@venizia/ignis-helpers`, `@venizia/ignis`): the `doThrow` option of `AES.encrypt`, `AES.decrypt`, `RSA.encrypt` and `RSA.decrypt` is removed and a failure always throws; a call that still passes it, with any value, throws `The doThrow option was removed`. Catch the exception where a fallback is wanted.
- **AES chooses its own IV** `remove-aes-iv-option` (`@venizia/ignis-helpers`, `@venizia/ignis`): `AES.encrypt` draws a fresh random IV on every call, and a call to `encrypt` or `decrypt` that passes `iv` throws `The iv option was removed`. Remove the option. Existing ciphertext still decrypts, because the IV is read from the envelope.
- **Every route has a 5 MiB request body limit** `default-body-limit` (`@venizia/ignis-kernel`, `@venizia/ignis`): with no `middlewares.bodyLimit`, a body over 5 MiB answers `413` (`core.request.body_too_large`) instead of Bun's 128 MiB. Set `middlewares.bodyLimit` in the application config, or give one route `BodyLimits.route({ maxSize })`. A `hono/body-limit` added in `setupMiddlewares()` now runs after the framework limit; move it into the config.
- **The url guard refuses credentials and more IPv6 ranges** `url-policy-refuses-userinfo-and-ipv6-ranges` (`@venizia/ignis-helpers`): `UrlPolicy.assertSafeUrl` refuses a url with a username or password (`URL_REFUSED`, no policy flag to allow it), and `isNonPublicAddress` treats NAT64, 6to4, IPv4-compatible, multicast, site-local, documentation, Teredo and other reserved IPv6 ranges as non-public. Send credentials in a header.
- **JWT configuration needs an issuer** `jwt-claims-required` (`@venizia/ignis-kernel`, `@venizia/ignis`): every JWS and JWKS configuration needs `claims: { issuer }`, with an optional `claims.audience`. IGNIS stamps them on every token it signs and requires them on every token it verifies, so a token signed with the same key for another purpose no longer authenticates a request. `sign`, `verify.issuer` and `verify.audience` are gone (a configuration that still passes them refuses the boot and points to `claims`), the accepted algorithm is pinned to `headerAlgorithm` (`HS256` by default) or the issuer's `algorithm`, and a JWKS verifier needs `verify.algorithms`. A present `audience` must be a non-empty string or list of them; without one, no `aud` is stamped or checked. Tokens issued before the upgrade carry no `iss` and are refused, so users sign in again.
- **The JWT secret has a minimum length** `jwt-secret-min-length` (`@venizia/ignis`): a `jwtSecret` shorter than 32 UTF-8 bytes refuses the boot, and `JWSTokenService` refuses it when built. The message says how to generate one. Changing the secret signs every user out.
- **A JWKS URL must use https** `jwks-url-https` (`@venizia/ignis-kernel`, `@venizia/ignis`): a `jwksUrl` of a JWKS verifier or of a service-assertion caller must be `https:`, except for loopback hosts or hosts you list in `jwks.hosts.http`. An entry is a host name, an IPv4 address or a bracketed IPv6 address, with an optional port; matching is exact, with no wildcard, range or CIDR, and an entry the URL parser would rewrite refuses the boot. Redirects are not followed. An app with a plain-http JWKS URL stops booting until it uses `https:` or lists the host.
- **Router getters are typed Hono** `rest-router-type-hono` (`@venizia/ignis-kernel`, `@venizia/ignis-worker`, `@venizia/ignis`): `getServer()` and `getRootRouter()` on `RestApplication`, `WorkerApplication` and `IApplication` return `Hono`, not `OpenAPIHono`, so a worker without controllers no longer bundles zod. Routers become `OpenAPIHono` when a REST controller loads, and `ServerApplication` always builds `OpenAPIHono`. Code that calls `.openapi()`, `.doc()` or `.openAPIRegistry` on a worker's router overrides `createRouter({ strict })` and the getter.
- **CrudControllerFactory.build replaces ControllerFactory.defineCrudController** `crud-controller-factory-build` (`@venizia/ignis`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`): `ControllerFactory` is now `CrudControllerFactory` and `build({ repository, routes })` takes the repository class, whose `@repository({ model })` supplies the entity. The path lives on `@controller({ path })`, `routes` lists exactly the routes you want (`CrudRoutes.READ` lists the four read routes), and `controller.basePath`, `controller.name`, `controller.readonly`, `controller.enabledRoutes`, a route's `enabled` and the type arguments are gone. Generated routes register after `binding()`, so a `super.binding()` call does nothing and a custom `GET /count` now shadows the generated one. `assertWriteVerbsDeclareAuthorize` takes `{ repositoryName, authorize, routes }` and `registerRepositoryInjection` loses `controllerName`. Type a route map for one repository as `TCrudRoutes<ItemRepository>`: `restoreById` and `restoreBy` fit only a repository that has both restore methods, and a bare `TCrudRoutes` lists every route.
- **SearchControllerFactory.build replaces defineSearchController** `search-controller-factory-build` (`@venizia/ignis-connectors`): `build({ repository, routes: { search: { use: true }, multiSearch: { use: true } }, authenticate })` takes the repository class, with the path on `@controller` and `isStrict` at the top level. Both routes were on before unless switched off, so switch both on to keep them: a route is a toggle, and one left out or `{ use: false }` is not served. `authenticate` is required: `{ strategies: [Authentication.STRATEGY_JWT] }` admits a JWT caller only, `{ skip: true }` opens the routes on purpose (and drops `authorize`, as for any route), and a config with neither throws when the controller is built, so a route is never open by omission. A repository class that extends `DefaultSearchRepository` must name its document type, as in `DefaultSearchRepository<TArticle>`.
- **Model settings group the hidden and stamped properties** `model-properties-group` (`@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`): `hiddenProperties` is `properties.hidden`, and `getServerStampedKeys()` is `properties.stamped`, which defaults to `createdBy`, `modifiedBy`, `createdAt`, `modifiedAt` and `deletedAt` for every model. Any `@model` that still sets `hiddenProperties` throws when the class is declared. The generated create and update bodies drop the stamped keys, so a hand-declared audit column the client used to send is dropped too; declare `properties: { stamped: [...] }` without it. A controller over a refined or transformed schema with stamped keys and no `routes.<route>.request.body` throws while it is built. `AuditFields` moves to the kernel.
- **deletedAt changes only through delete and restore** `deleted-at-writes-refused` (`@venizia/ignis-connectors`): on `SoftDeletableRepository` and its SQLite twin, `updateById`, `updateBy`, `updateEach` and `upsert` answer `400` to a `data` that holds `deletedAt`, with any value. Delete with `deleteById`, `deleteBy` and revive with `restoreById`, `restoreBy`. See `soft-delete-writes-data`.
- **updateAll, deleteAll and restoreAll are removed** `remove-bulk-all-methods` (`@venizia/ignis`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`): `updateBy`, `deleteBy` and `restoreBy` are the only bulk methods, with no alias, and their `where` is required. The whole table is `where: {}` with `options.force: true`. This covers the relational, search and HTTP repositories. A subclass or mock that overrode the removed names must override the `By` names.
- **The migration ledger takes a schema and a table** `migration-ledger-option` (`@venizia/ignis-connectors`): `RelationalMigrationRunner` places its ledger with `ledger: { schema?, table? }`, and `ledgerTable` is removed (a runner that still passes it throws at construction). The defaults are unchanged. Postgres creates a missing schema, and SQLite accepts only `main`.
- **A datasource's connector field can be undefined** `datasource-connector-optional` (`@venizia/ignis-kernel`, `@venizia/ignis-connectors`): `connector` is typed `TConnector | undefined`, because a datasource that opens on first use has none before that, and none after `close()`. Call `getConnector()`, which throws until the datasource is open. See `datasource-open-first-use`.
- **Statuses.isValid checks the shape of a code** `statuses-is-valid-shape` (`@venizia/ignis-kernel`): `isValid` is true for any `NNN_NAME` code (a digit 0 to 5, two digits, an underscore, then upper-case letters, digits and underscores), not only the built-in ones, and the category checks read the leading digit. Code that relied on `isValid` refusing a well-formed unknown code must use `Statuses.SCHEME_SET.has(status)`. A subclass that already defines one of the seven new codes or names for another meaning must pick another. See `statuses-subpath`.
- **A mail verification token has a 16 byte minimum** `mail-token-bytes-minimum` (`@venizia/ignis`): `RandomTokenGenerator` throws for a `tokenBytes` below 16, because a shorter token can be guessed offline. Raise it to 16 or more; 32 is the usual setting. See `token-uid-helpers`.
- **The static-asset names share one prefix** `static-asset-names` (`@venizia/ignis`, `@venizia/ignis-helpers`, `@venizia/dev-configs`): every exported name of `@venizia/ignis/static-asset` starts with `StaticAsset`, with no alias. Helper classes end in `Utility`, constants are class members (`StaticAssetDefaults.PENDING_PREFIX`, `StaticAssetMetaLinkCodes.CREATE_FAILED`, `StaticAssetContentTypes.RENDERABLE`), `StaticAssetComponentBindingKeys` is `StaticAssetBindingKeys` and its option key string is `@app/static-asset/options`. `AssetControllerFactory.defineAssetController` and `AuthControllerFactory.define` are both `build`. Removed: `WHITELIST_HEADERS`, `findLabelsInQuery`, `StaticAssetStorageTypes` (use `StorageTypes` from the helpers) and the `isValid` and `SCHEME_SET` of `MetaLinkRecreateActions`; `buildObjectLink` is `StaticAssetObjectLinkUtility.build` and `resolveServedContentType` is `StaticAssetServe.resolveServedContentType`.
- **A static-asset entry serves one bucket, with a toggle per feature** `static-asset-entry-flat` (`@venizia/ignis`, `@venizia/ignis-helpers`): an entry is one flat object with a required `bucket` that never appears in a URL, and `serverUpload`, `directUpload`, `metaLink` and `directUpload.validation` are each `{ use: false }` or `{ use: true, ...options }`. `controller`, `extra` and `storage` are gone, the bucket-management routes are removed, `useMetaLink` is `metaLink: { use: true, repository }`, `defineRoutesBefore` and `defineExtraRoutes` are `extend.before` and `extend.after`, and `serverUpload.objectKey` replaces the naming hooks. The disk spool and `directUpload.onCommit` are gone: check the file in `validation`. Direct upload needs a `keyPrefix`, labels come from the body only, and the folder error codes are now `core.storage.folder_path_invalid` and `core.storage.folder_depth_exceeded`. Links stored with `/buckets/<name>/` need rewriting. See `static-asset-auth`.
- **A direct-upload policy signs one object** `direct-upload-one-object-per-policy` (`@venizia/ignis-helpers`, `@venizia/ignis`): `presignPost` takes `object: { key }` in place of `keyPrefix` and signs that key, so `formData` carries the `key` and the client no longer appends it. `directUpload.expiresIn` is `directUpload.expires.upload`, with a separate `expires.commit` for the token. The commit token has a new format, so a token issued before the upgrade stops verifying and the client asks for a new policy. `upload-commit` now calls `authorize` first.
- **Direct upload takes resolvers and commits once** `direct-upload-resolvers` (`@venizia/ignis`, `@venizia/ignis-helpers`): `directUpload.resolvers.owner` is required, so a token never commits for whoever holds it, and `resolvers.metadata` signs per-file metadata into the token. `resolvers.commit.destination` picks the final key. A commit is single-use (a second one answers `409 core.static_asset.upload_already_committed`), `upload-policy` refuses a `fileName` that is a path, and a token is read strictly. With `validation` on, `upload-validate` pins the exact content it read and answers the `commitToken` that `upload-commit` takes, so a file cannot change between the check and the copy; the handler takes `{ file, owner, metadata }` instead of `{ bucket, object, helper }`. `getObjectStream` takes `ifMatch` and `versionId`, `copyObject` takes `ifMatch` and `sourceVersionId`, and `BunS3Helper.getStat` reports `versionId`. See `static-asset-upload-validate`.
- **A server upload gets a unique key** `static-asset-unique-upload-key` (`@venizia/ignis`): without `serverUpload.objectKey`, a file is stored as `<keyPrefix><folderPath>/<uuid>/<name>`, so a second upload of `report.pdf` no longer overwrites the first. A URL built from the file name stops finding the object: use the `link` or `object.key` the upload answers, or set `serverUpload.objectKey`.
- **normalizeObjectName is public and static** `storage-normalize-object-name` (`@venizia/ignis-helpers`): `BaseStorageHelper.normalizeObjectName(opts)` replaces the protected instance method, so a naming hook can start from the key the helper would have written. A helper subclass that overrode the protected method moves the logic to a hook.
- **BaseStorageHelper.getObjectStream is not implemented by the base** `storage-get-object-stream` (`@venizia/ignis-helpers`): the base now throws `is not supported by this helper` instead of buffering a whole read to cut a range. `BunS3Helper` and `DiskHelper` already override it. A custom helper that relied on the default implements it itself.
- **The mail queue config is a union on type, and BullMQ takes a Redis helper** `mail-queue-executor-config` (`@venizia/ignis`): `IMailQueueExecutorConfig` is `TMailQueueExecutorConfig`, and the per-type `internalQueue` and `bullmq` fields become `options`, which the compiler now requires. For BullMQ, `options.redis` is an `IRedisHelper` you create (`RedisSingleHelper`, `RedisSentinelHelper` or `RedisClusterHelper`), so the queue runs on Sentinel and Cluster. You close the helper: the executor's `close()` closes its workers and queue and leaves the helper open. Set `maxRetry: -1` so it keeps reconnecting.
- **Mail template values are HTML-escaped** `mail-template-escaping` (`@venizia/ignis`): <code v-pre>{{value}}</code> is escaped in the body, and <code v-pre>{{{value}}}</code> inserts markup you trust as it is. A value you escaped by hand is now escaped twice. `render()` takes `format: MailTemplateFormats.HTML` (default) or `TEXT`, and the subject of `sendTemplate()` is rendered as `TEXT`.
- **sendTemplate keeps what it renders** `mail-send-template-options` (`@venizia/ignis`): `options.to` and `options.html` no longer replace the recipients or the rendered body, and `options.requireValidate` is no longer sent as a message field. Call `MailService.send()` to choose the recipients and body yourself.
- **MailErrorCodes keeps only the server-side codes** `mail-error-codes-catalog` (`@venizia/ignis`): the seven codes that `MailErrors` already defines (`INVALID_CONFIGURATION`, `INVALID_RECIPIENT`, `INVALID_HEADER`, `TEMPLATE_NOT_FOUND`, `ATTACHMENT_PATH_REFUSED`, `ATTACHMENT_TOO_LARGE`, `BODY_SOURCE_REFUSED`) are removed from `MailErrorCodes`. Read `MailErrors.<code>.message.code`. The wire codes are unchanged.
- **ITemplate.render is removed** `itemplate-render` (`@venizia/ignis`): nothing read or wrote the field. Delete any reference to it.
- **Three mail validators are removed** `mail-validators-removed` (`@venizia/ignis`): `MailQueueExecutorTypes`, `BullMQExecutorModes` and `MailBackoffTypes` lose `isValid` and their value sets (`SCHEME_SET`, `MODE_SET`). The constants are unchanged.
- **Unused validators are removed from the helper constants** `helper-validators-removed` (`@venizia/ignis-helpers`): `isValid` and `SCHEME_SET` are gone from `S3Audiences`, `QueueStatuses`, `BullQueueRoles`, `KafkaHealthStatuses`, `KafkaBrokersDownReasons`, `FetcherVariants`, `UrlSchemes`, `TcpClientStates`, `MimeTypes`, `DataTypes`, `FieldMappingDataTypes` and `RedisSentinelRoles`. The constant values do not change.
- **RedisHelperFactory has one method per topology** `redis-factory-per-topology` (`@venizia/ignis-helpers`): `RedisHelperFactory.create({ mode, ... })`, `RedisModes` and `TRedisMode` are removed. Call `single`, `cluster` or `sentinel` with the same options, without `mode`. The `namespace-functions` codemod cannot pick the topology, so change each call by hand.
- **The Redis user option is replaced by username** `redis-single-user-option` (`@venizia/ignis-helpers`): `RedisSingleHelper` accepted `user` and never read it. It now takes `username`, which goes to ioredis beside `password`, so a node that uses ACL users can be reached. Rename the option; with `username` set the helper authenticates as that user.
- **Redis helpers reconnect by default** `redis-default-retry` (`@venizia/ignis-helpers`): `maxRetry` defaults to `5` on the single and Sentinel helpers (it was `0`, which gave up at the first failed attempt), and the wait is exponential from 1 s to 30 s instead of 2 s, 4 s, then 5 s. `0` still means no reconnect and `-1` reconnects forever. A negative number other than `-1`, a fraction or `NaN` throws when the helper is built. The cluster helper takes `maxRetry` too (default `5`; it used the ioredis strategy, which never stops, so a cluster that must keep trying sets `-1`) and sets `maxRetriesPerRequest: null` by default, which BullMQ workers need.
- **Sentinel options move into a sentinel scope** `redis-sentinel-scope` (`@venizia/ignis-helpers`): `masterName`, `role`, `sentinels` (now `nodes`), `sentinelUsername` and `sentinelPassword` (now `username` and `password`) move into `sentinel`. Top-level `username` and `password` are always the data nodes' credentials. A JavaScript caller that keeps the old shape (`sentinels` or `masterName` at the top level) gets a clear error when the helper is constructed (`sentinel.nodes is required`), and one that keeps the old credential fields has them ignored, so move them before you deploy.
- **A cluster takes its credentials once** `redis-cluster-node-password` (`@venizia/ignis-helpers`): `nodes[].password` is removed, and top-level `username` and `password` apply to every node, including nodes found after startup (ioredis applied a per-node password to the startup nodes only, so replicas and failovers answered `NOAUTH`). A node's `port` defaults to `6379`, and a given top-level credential wins over `clusterOptions.redisOptions`.
- **BullMQHelper takes explicit type arguments** `bullmq-helper-type-arguments` (`@venizia/ignis-helpers`): the default generics and the worker callbacks use `unknown` instead of `any`, and `onWorkerData` returns `Promise<TQueueResult>`. A helper typed `BullMQHelper<TElement, unknown>` no longer assigns to `BullMQHelper<unknown, unknown>`. Pass `BullMQHelper<TElement, TResult>` with handlers typed `(job: Job<TElement, TResult>) => Promise<TResult>`.
- **Storage metadata types use unknown** `storage-metadata-types-unknown` (`@venizia/ignis-helpers`): the index signatures of `IUploadFile` and `IObjectMetadata`, `IUploadResult.metaLink.data` and the `options` of `IStorageHelper.getObject` use `unknown` instead of `any`. Narrow an extra field you read.
- **The inversion entry no longer loads reflect-metadata** `inversion-entry-reflect-metadata` (`@venizia/ignis-inversion`, `@venizia/ignis-kernel`): importing `getError` in a browser no longer pulls the 44 KB polyfill, because the modules that call `Reflect.*Metadata` import it themselves. Browser code that calls `Reflect.getMetadata` or a sibling directly must import `reflect-metadata` once at its entry. Servers are unaffected.
- **HttpDataSource is a DataSourceRoot, not an AbstractDataSource** `http-data-source-root-class` (`@venizia/ignis-connectors`, `@venizia/ignis-kernel`): the protected `network` member is gone, `instanceof AbstractDataSource` is false for an `HttpDataSource`, and `discoverDefinitions()` and `getBoundModelClasses()` are not available to its subclasses. Send through your own function with `settings.fetch`, and test with `instanceof DataSourceRoot` or `isDataSourceClass`. `@datasource({ open: { on: 'first-use' } })` on an `HttpDataSource` subclass is still refused at boot, and `open.timeoutMs` is no longer read. ## Added
- **A model can be scoped through its parent** `access-through` (`@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`): `settings.access: { through: ScopeThrough.of({ entity, relation }) }` gives a child with only a foreign key its parent's row scope for reads and writes, so no tenant column is copied. A create or a move must name a parent the caller may reach (a missing, foreign or null parent gives the same 403), the parent's `write.sharedRows` holds at every hop, and several hops chain up to 5. ## Security
- **Run the IGNIS tools with `bun run`, never `bunx`** `unscoped-bin-names` (`@venizia/dev-configs`, `@venizia/ignis`): the npm names `vulcan`, `devz`, `ardor` and `ignis` belong to unrelated packages, so `bunx devz`, `bun x vulcan` and `npx vulcan` can run foreign code, and `--no-install` does not protect against a copy an earlier bare run cached. Change your scripts, Makefiles, git hooks, workflows and docs to `bun run devz ...` or `node_modules/.bin/devz ...`, pin the version of any repeated `bun x @venizia/...` command, and delete `~/.bun/install/cache/.bunx-*/{vulcan,devz,ardor,ignis,vulcan-atlas}@*`.
- **The access scope is combined with the caller's where by AND** `access-scope-anded-with-where` (`@venizia/ignis-connectors`, `@venizia/ignis`): the row scope of `access.resolve` is ANDed with the `where` of every read, count, update, delete and include whatever its shape, so a `where` can only narrow it. Before, a scope written as one value per column could be replaced by a `where` on the same column.
- **The error response redacts extra** `error-response-redaction` (`@venizia/ignis-kernel`, `@venizia/ignis`): `extra` goes through the redaction the log line uses, a 5xx in production carries only `requestId` and `upstreamRequestIds`, and a cycle or a BigInt no longer turns the status into a plain 500.
- **The validation response carries no raw error in production** `validation-response-no-raw-cause` (`@venizia/ignis-kernel`, `@venizia/ignis`): `details.cause` of a 422 holds the issue list in production, or is absent when the message is not a list.
- **Redaction covers more keys and the credentials inside strings** `redaction-key-and-string-coverage` (`@venizia/ignis-helpers`, `@venizia/ignis`): the logger and error handler mask more key names (`credential` and its prefixed forms, `secretAccessKey`, `signingKey`, `jwt`, `sessionId`, `otp`, `cvv`, `ssn`, ...) and scrub the password of a url, `Bearer` or `Basic` values and credential query parameters wherever they sit in a string. `primaryKey`, `cacheKey`, `code` and `pin` stay visible. Set `APP_ENV_LOGGER_DO_REDACT=false` locally to read the values.
- **The derived-key cache is bounded** `derived-key-cache-bounded` (`@venizia/ignis-helpers`): the AES and RSA helpers keep at most 64 derived keys, keyed by a SHA-256 digest, so memory no longer grows with each distinct secret and no secret is held in a key.
- **The health-check stats secret is compared in constant time** `health-stats-secret-constant-time` (`@venizia/ignis`): `stats.secretKey` of `GET /health/stats` is checked with `Hash.equals`; a missing or non-string header is refused.
- **Object keys and bucket names refuse control, bidirectional and separator characters** `object-key-separators` (`@venizia/ignis-helpers`, `@venizia/ignis`): `isValidSegment` (so `isValidObjectKey` and `isValidBucketName`) refuses any control character, a lone surrogate, the bidirectional marks and overrides, and the line and paragraph separators U+2028 and U+2029, and `isValidOriginalName` refuses the bidirectional set and the same separators. Names in any script stay valid.
- **The WebSocket server ignores a frame that is not a message** `websocket-ignores-non-message-frames` (`@venizia/ignis-helpers`): a frame that is not an object with a string `event` is logged by size and dropped, so one frame such as `null` can no longer throw before authentication.
- **A where key that names the prototype is refused** `where-prototype-keys-refused` (`@venizia/ignis-connectors`, `@venizia/ignis`): `__proto__`, `constructor` and `prototype` answer `400 Column NOT FOUND` in a `where`, `order` or update data, and the default-filter merge refuses them first. Column lookups read the table's own columns only.
- **Meilisearch highlights carry no hidden field** `meilisearch-highlights-hidden-fields` (`@venizia/ignis-connectors`): a hit's `highlight` is shaped like its document on every engine, and a model that hides fields sends `attributesToRetrieve` with the visible fields so the engine does not return a hidden value at all.
- **Storage log lines escape a caller's key** `storage-log-escape` (`@venizia/ignis-helpers`): a key, segment, bucket or file name chosen by the caller is quoted and escaped before a storage helper logs it, so it cannot forge a line or hide text, and the messages of the errors a helper throws get the same escaping without quotes. Update a log pattern that matched the bare value.
- **Mail checks headers for every transport and expires failed jobs** `mail-header-check` (`@venizia/ignis`): `MailService.send()` refuses an address, subject or header value with a line break, CR or NUL with `400 core.mail.invalid_header` on every transport, and `fromName` is escaped. Failed BullMQ mail jobs are kept seven days and at most 1000 (`MailDefaults.FAILED_JOB_RETENTION`) instead of forever, and queuing a mail logs the job id, no longer the address. A transport you call directly skips the check.
