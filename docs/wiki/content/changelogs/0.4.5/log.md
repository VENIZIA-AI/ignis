A small release with no breaking change. A peer that ships both an ES module and a CommonJS build (`bullmq`, `socket.io-client`, the `@connectrpc` peers) is now loaded as the copy your own `import` gets, `devz check` gains four commands for trimming tests, and `assertApplicationBoots` stops reporting false duplicate routes. The other packages are republished at 0.4.5 with no code change; update all of them together.

## Added

- **`ModuleUtility.preload`** `module-preload` (`@venizia/ignis-helpers`): `await ModuleUtility.preload({ modules })` loads each module with `load` and registers it, so the synchronous `loadSync` that a constructor must use returns the ES module copy afterwards. Call it once at the entrypoint, before the helpers are built: `await ModuleUtility.preload({ modules: ['bullmq', 'socket.io-client'] })`. Only an app that imports `bullmq` or `socket.io-client` itself and compares classes with `instanceof`, or passes their instances to the helpers, needs it. The other way is to pass the module to the one helper, for example `new BullMQHelper({ ..., module: await import('bullmq') })`. Without either, `BullMQHelper` and `SocketIOClientHelper` still read the CommonJS copy in their constructors, as in 0.4.4.
- **Four `devz check` commands for trimming tests** `dev-configs-test-trim-checks` (`@venizia/dev-configs`): `devz check test-weight <junit.xml>...` prints totals, time per package, the heaviest files, the same suite and case name in more than one file, files with no assertions and skips from the report of `bun test --reporter=junit`. `devz check test-dead-code` lists fixtures and helpers under `__tests__` that no other file refers to (candidates, not verdicts). `devz check test-mutate <ledger.json>` replays a mutation ledger: the survivor test must go red under each break, and files are restored byte for byte. `devz check test-controls <registry.json>` fails when a registered positive-control test is gone, or, for an entry with `"kind": "file"`, a negative fixture file. `@venizia/dev-configs/checks` also exports `analyseJunit`, `findDeadTestCode`, `replayLedger`, `checkControls` and `listTestTitles`. Nothing runs unless you call it; nobody has to change anything.
- **`assertApplicationBoots` names the component that failed** `boot-helper-component-hint` (`@venizia/ignis`): when the boot rejects while a component's `configure()` runs (for example one that opens Redis, Kafka or S3), the helper logs one warning that names the component and suggests `skipComponents: ['Name']`, and `skipBindings` for the services that depend on it. The rejection is still the original error. No action needed.

## Changed

- **`ModuleUtility.load` resolves the ES module copy** `module-load-es-copy` (`@venizia/ignis-helpers`, `@venizia/ignis`): `load` resolves a peer from the project root with the `import` condition of its `exports` map, so a peer that ships both builds comes back as the instance your own `import` gets, not a second one. A module the project root cannot resolve is imported by name as before, and a registered module still wins. Code that calls `load` for a dual-build peer now gets the ES module copy (named exports on the namespace); a CommonJS-only peer still arrives as `{ default: <exports> }`. `loadSync` is unchanged. The gRPC adapter now loads `@connectrpc/connect` and `@connectrpc/connect/protocol` with `load`, so a peer registered with `ModuleUtility.register` satisfies it, which a binary built with `bun build --compile` needs; you can register both entry points instead of passing `module`.

## Fixed

- **No false duplicate routes in the boot helper** `boot-helper-false-duplicate-routes` (`@venizia/ignis`): `assertApplicationBoots` reported "mounted more than once" for every route that had a validator, an authenticate step or an authorize step. It now counts a controller once per method and path. A real duplicate is still reported: two controllers on the same method and path, or one controller that declares the same pair twice through decorators (the message then says `(declared 2 times)`). A test that passed `{ routes: false }` only to get past the false report can drop it.
- **The tmpdir preload is passed in the test script** `tmpdir-preload-in-test-script` (`@venizia/dev-configs`, `@venizia/ignis`): bun reads only the `bunfig.toml` of the folder it runs in, so `[test] preload` in the repository root does not cover `bun test` run inside a package. Pass `--preload @venizia/dev-configs/testing/tmpdir-preload` in the package's `test` script instead. The `ignis` app and lib presets now do this; an existing app edits its `test` script. The 0.4.4 notes had said a `bunfig.toml` was enough.
