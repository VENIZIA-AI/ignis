IGNIS 0.5.0 is a typing and network release. Binding keys carry the type of their value, the fetchers and the url guard are one family that validates, retries and guards each call, and the origins you trust are named in one format for the url guard and for JWKS. It also adds mail template sections, Typesense import options and BullMQ job metadata. Several changes are breaking, and each entry says what to change.

## Breaking
- **RetryHelper is RetryUtility** `retry-helper-is-utility` (`@venizia/ignis-helpers`, `@venizia/ignis`): `RetryHelper` only had static members, so it is renamed `RetryUtility` with the same members. It no longer extends `BaseHelper`, so `instanceof BaseHelper`, the inherited constructor and the instance logger are gone. Run `bun node_modules/.bin/devz codemod class-renames [paths...] --write` to rename the import and every use. No alias is kept.
- **SlugHelper is SlugUtility** `slug-helper-is-utility` (`@venizia/ignis-helpers`, `@venizia/ignis`): `SlugHelper` only had static members, so it is renamed `SlugUtility` with the same members. It no longer extends `BaseHelper`. Run `bun node_modules/.bin/devz codemod class-renames [paths...] --write` to rename the import and every use. No alias is kept.
- **CredentialHelper is CredentialUtility** `credential-helper-is-utility` (`@venizia/ignis-helpers`, `@venizia/ignis`): `CredentialHelper` only had static members, so it is renamed `CredentialUtility` with the same members. Run `bun node_modules/.bin/devz codemod class-renames [paths...] --write` to rename the import and every use. No alias is kept.
- **RejectionHelper is RejectionUtility** `rejection-helper-is-utility` (`@venizia/dev-configs`): `RejectionHelper` only had static members, so it is renamed `RejectionUtility` with the same members. Run `bun node_modules/.bin/devz codemod class-renames [paths...] --write` to rename the import and every use. No alias is kept.
- **SpawnHelper is SpawnUtility** `spawn-helper-is-utility` (`@venizia/dev-configs`): `SpawnHelper` only had static members, so it is renamed `SpawnUtility` with the same members. Run `bun node_modules/.bin/devz codemod class-renames [paths...] --write` to rename the import and every use. No alias is kept.
- **parseContentDisposition moves to HttpResponseReader** `parse-content-disposition-in-reader` (`@venizia/ignis-helpers`, `@venizia/ignis`): `RequestUtility.parseContentDisposition({ header })` is now `HttpResponseReader.parseContentDisposition({ header })` and returns the same answer. A browser client can read the header without importing `RequestUtility`, which needs `node:*`. `ContentDispositionTypes` is imported as before. Replace the call by hand. `devz codemod namespace-functions` only rewrites the older bare `parseContentDisposition` function to the new method.
- **HttpDataSource works with a Headers object** `http-datasource-headers-object` (`@venizia/ignis-connectors`, `@venizia/ignis`): the protected `configuredHeaders`, `resolveHeaders()` and the `requestHeaders` option of `buildHeaders()` are now a `Headers`, not arrays of `[name, value]` pairs. The connectors' own `THttpHeaders` is gone: use the `THttpHeaders` of `@venizia/ignis-helpers`, which is a `Headers`, pairs or a record. A number value is sent as text. A `null` value removes the header, but only within the same layer: a call's `null` does not remove a configured or resolved header. If a subclass overrides `buildHeaders` or `resolveHeaders`, update the types it reads and returns. `settings.headers`, `headersResolver` and a call's `headers` accept what they accepted before. There is no codemod.
- **HttpResponseReader moves to @venizia/ignis-helpers** `http-response-reader-in-helpers` (`@venizia/ignis-helpers`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`): import `HttpResponseReader` from `@venizia/ignis-helpers` (or `/core`), no longer from `@venizia/ignis-kernel/repository` or `@venizia/ignis-connectors/http`. Its `isPlainObject` is now `RecordUtility.isPlainObject`, and `toText` is private. Change the import; the methods are the same. There is no codemod.
- **allowedHosts is replaced by hosts.trusted and hosts.strict** `url-safety-hosts` (`@venizia/ignis-helpers`): `IUrlSafetyPolicy.allowedHosts` is removed. List exact origins in `hosts.trusted`, and add `strict: true` if nothing else may pass. A policy that still carries `allowedHosts` throws a configuration error that names the replacement, because dropping it silently would turn "only these hosts" into "any public host". A trusted origin also passes when it resolves to a private address.
- **jwks.hosts.http is replaced by jwks.trusted** `jwks-trusted-origins` (`@venizia/ignis-kernel`, `@venizia/ignis`): list the hosts a JWKS may be fetched from over `http:` as exact origins (`http://identity-service`, `http://10.0.0.5:8080`) in `jwks.trusted`. It covers the JWKS verifier and the service-assertion callers. Each port is its own entry; an entry without a port used to mean every port. An app that still sets `jwks.hosts.http` refuses to boot on its http JWKS URL until you list the origin.
- **The inner JWT options have keys of their own** `jwt-inner-option-keys` (`@venizia/ignis-kernel`, `@venizia/ignis`): `AuthenticateBindingKeys.JWT_OPTIONS` now holds only what your app binds, the `TJWTTokenServiceOptions` with its `standard`. Before, the component re-bound the same key to the inner `IJWSTokenServiceOptions`, and `JWKS_OPTIONS` held the issuer's or the verifier's options depending on the mode. Now `JWS_OPTIONS`, `JWKS_ISSUER_OPTIONS` and `JWKS_VERIFIER_OPTIONS` each hold one type, and `JWKS_OPTIONS` is removed. Nothing changes if your app binds `JWT_OPTIONS` and registers `AuthenticateComponent`. If a service of yours injects `JWT_OPTIONS` or `JWKS_OPTIONS` to read the inner options, inject the new key.
- **A binding key is made by BindingKeys.build&lt;T&gt; and nothing else** `binding-keys-required-brand` (`@venizia/ignis-inversion`, `@venizia/ignis-kernel`, `@venizia/ignis`): `bind`, `get`, `gets`, `getBinding`, `isBound`, `unbind`, `Binding.bind` and `@inject({ key })` accept only a key made by `BindingKeys.build<T>({ namespace?, key })`. A raw string, a template literal, a symbol and the `{ namespace, key }` object form of `get` and `getBinding` no longer compile, and `build` needs its type argument (`build<unknown>` when a key has no common value type). Key strings do not change, so nothing stored or sent changes. Run `devz codemod binding-keys`: it rewrites each literal key, moves the type your call already claimed into `build<T>`, and lists each key it left as `build<unknown>` so you can name the real type. A key your app keeps in a constant, such as `static readonly MAILER = 'services.Mailer'` in a key class, is built where it is declared, in any file of the run: `static readonly MAILER = BindingKeys.build<Mailer>({ key: 'services.Mailer' })`. The places that use `Keys.MAILER` are not edited, because the constant is still a string and now carries `Mailer`. For `T` the codemod uses the one type your code already claims where the key is used (`container.get<Mailer>`, the type of the decorated parameter), only when every name in it means the same type in the file that declares the constant (it adds no import); otherwise it writes `unknown`, and it does so too when no site claims a type or the sites differ (listed as `type`: name it). It builds a const, a `readonly` property and a property of an object literal under `as const` that has a string value and no type annotation, a computed one included (`` `${namespace}.Name` ``, `Mailer.name`). It lists as manual, and leaves alone, a `let`, a property that is not `readonly`, an object literal without `as const`, a declaration with a type annotation, a parameter, a call that returns a key, a declaration outside the files you pass, and a key of a package you do not own. Run it once over the whole project (from the root, or with every package path as arguments): a constant declared in a file outside the run is listed as manual and not edited. The codemod uses the compiler options of the nearest `tsconfig.json` above the folder you run it in; the files you pass are its roots, not the tsconfig's `include`, and there is no flag to choose another tsconfig: a test file whose imports need its own package's tsconfig (path aliases, test types) can leave a receiver unresolved, and the site is listed "the receiver's type is not resolved" and left alone. Run the codemod again from that package's folder for those files, or change them by hand. A key written inline with no claimed type is `build<unknown>` too, so the `type` list can be long: name each from your typecheck. A key written as `SomeClass.name` is the built-in `name` of a class, not a constant of yours: the codemod builds it in place, `BindingKeys.build<SomeClass>({ key: SomeClass.name })`. A keys file that imports nothing from the framework is listed "pass --import-from" and is not built until you pass `--import-from @venizia/ignis`. Where your code needs the literal type of a built constant (`typeof Keys.MAILER` as a type, a literal union, a parameter typed `'services.Mailer'`) or assigns to it, the typecheck now names the site. `BindingKeys.build` throws on an empty key, so a computed constant that comes out `''` now throws when its class loads. Change a `Symbol` key to a string key by hand. `@inject({ target: Class })` stays the form for a class. A library key that is still a plain string (ARDOR's `CoreBindings` before its release with typed keys, which follows this one) needs the library's typed version; the codemod lists such a key as manual. Reflect-metadata keys (`MetadataRegistry.define`/`get`) are `TMetadataKey`, a plain string or symbol. `@provide({ key })`, the `key` of an event handler `{ type: BINDING_KEY, key }` and the `serviceKey` of the auth controller take a built key too.
- **UrlIngest.fetchGuarded, capStream and readCappedBody are removed** `fetch-guarded-removed` (`@venizia/ignis-helpers`, `@venizia/ignis`): the guard now lives in the fetchers. Give a `NativeFetcher` or `AxiosFetcher` `guardEngine: UrlGuard`, and pass `guard`, `maxBytes`, `signal`, `maxRedirects` and `retry` on the call. `BodyLimit.capStream` and `BodyLimit.readBytes` replace the two body helpers. `StaticAssetIngestUtility.fromUrl` already does this.
- **NodeFetcher is now NativeFetcher** `native-fetcher-rename` (`@venizia/ignis-helpers`, `@venizia/ignis`): `NodeFetcher`, `NodeFetchNetworkRequest`, `INodeFetch*` and `FetcherVariants.NODE_FETCH` (`'node-fetch'`) are now `NativeFetcher`, `NativeFetchNetworkRequest`, `INativeFetch*` and `FetcherVariants.NATIVE` (`'native'`). No alias is kept. Rename them by hand with the table in the migration steps; there is no codemod.
- **send&lt;T&gt; is removed; pass a schema** `fetch-send-type-argument-removed` (`@venizia/ignis-helpers`): every verb and `send` take a zod `schema` and answer `{ data, status, headers, response }`, with `data` typed by `z.infer`. Without a schema the call answers the raw `Response` (`AxiosResponse`), as before.
- **A status outside 2xx throws** `fetch-non-2xx-throws` (`@venizia/ignis-helpers`, `@venizia/ignis`): both fetchers throw a `UrlFetchError` (with status, url, headers and response) instead of handing a 404 or 500 back as data. Use `acceptStatus` to opt out. The Axios default `validateStatus: status < 500` is gone, so a 4xx now throws too.
- **Headers merge per header, and defaultConfigs no longer carries headers or signal** `fetch-headers-merge` (`@venizia/ignis-helpers`): a call's headers merge with `defaults.headers` one header at a time. The call wins, and `null` or `undefined` removes a default. If your code relied on a call's headers replacing every default (a multipart upload without the JSON content type), remove that default with `null`. `NativeFetcher` takes `defaults.headers` in place of `defaultConfigs.headers`, and `timeout` now applies per attempt.
- **UrlIngest is merged into UrlGuard** `url-ingest-merged-into-guard` (`@venizia/ignis-helpers`, `@venizia/ignis`): `assertPublicHost`, `assertReachableUrl` and `resolvePublicAddresses` are now static methods of `UrlGuard`, next to `createRoute`, which a fetcher takes as `guardEngine`. The name `UrlIngest` no longer exists and no alias is kept. Rename by hand with the table in the migration steps; there is no codemod.
- **Exports with no caller are removed** `remove-unused-network-exports` (`@venizia/ignis-helpers`, `@venizia/ignis-connectors`, `@venizia/ignis`): these exports are gone: `QueryStringNullishModes`, `QueryStringNestedModes` and their types (`IQueryStringOptions.nullish` and `.nested` are now the literals `'empty' | 'skip'` and `'drop' | 'json'`), `TFetchResult`, `TUrlScheme`, `BodyLimit.DEFAULT_MAX_BYTES` and `FetchErrors` (the error code `core.fetch.schema_mismatch` is unchanged). From `@venizia/ignis-connectors/http`, `THttpQuery`, `TAuthTokenResolver`, `THttpHeadersResolver`, `HttpResourceEntity` and `THttpRepositoryOptions` are gone too (`THttpFetch` stays, as an alias of `TNativeFetchSender`). `UrlPolicy.readHosts` is no longer public. Rename or inline by hand with the table in the migration steps; there is no codemod.
- **getRequestUrl refuses paths that can leave the base** `get-request-url-strict-join` (`@venizia/ignis-helpers`, `@venizia/ignis`): `BaseNetworkRequest.getRequestUrl` now joins the base and the paths through the new `UrlBuilder.join`, the check the connectors' HTTP data source already ran. A path answers a `400` that starts `[<client name>] A request path must stay under the base path` when it is a dot segment (`..`, `%2e%2e`, `.%2e`, with a trailing space, or ended by `?` or `#`), or carries a backslash, `%5c` or a control character. A base with a `?` or a `#`, a path-relative base (`api`) and a result that leaves the base's origin or path are refused too. A relative base (`/api`) now answers the absolute url, resolved against the page's origin, and a path with a space is percent-encoded (`a%20b`).
- **A missing template value renders empty, and an object in a text slot throws** `mail-template-missing-empty` (`@venizia/ignis`): `TemplateEngineService` used to send a <code v-pre>{{key}}</code> the data did not have as literal text in the mail. It now renders nothing (`missing: 'empty'`, the default). Pass `missing: 'keep'` for the old output or `'throw'` to refuse. A value that is an object, a list, a date or a function in a <code v-pre>{{key}}</code> slot used to print `[object Object]` (or the function's source); it now throws `core.mail.template_invalid`. Resolve a locale object and format dates before rendering. Some text that used to pass through as literal now has a meaning: <code v-pre>{{#x}}</code> and <code v-pre>{{^x}}</code> open a section, and <code v-pre>{{/x}}</code>, <code v-pre>{{! x}}</code>, <code v-pre>{{> x}}</code>, <code v-pre>{{= x =}}</code> and <code v-pre>{{& x}}</code> throw `core.mail.template_invalid`. To keep such text literal, pass it as data and insert it with <code v-pre>{{{ }}}</code> (a value is never parsed as a template).
- **Value classes extend ConstClass and lose SCHEME_SET** `const-class-base` (`@venizia/ignis-helpers`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis-boot`, `@venizia/ignis`): every const class that held only string values (`AuthenticationModes`, `ArtifactTypes`, `DurationUnits`, `WebSocketEvents`, `SearchModes` and the like) now extends the new `ConstClass`, which gives it `values()` and `isValid(value)`. Their `SCHEME_SET` and their own `isValid` are removed: `X.SCHEME_SET.has(value)` is `X.isValid(value)` (it takes `unknown` and narrows the value), and `[...X.SCHEME_SET]` is `X.values()`. Run `bun node_modules/.bin/devz codemod const-classes [paths...] --write`; it rewrites those two forms and lists any other use of `SCHEME_SET` on these classes. Classes that hold more than a list of strings keep `SCHEME_SET`: the status classes, `DataSourceDrivers`, `AuthorizationActions`, `AuthorizationRoles`, `AuthorizationPolicyVariants`, `QueryOperators`, `ScopeOperations`, `LogLevels`, `KafkaAcks`, `PatternTokens` and `ArtifactStereotypes`.

## Added
- **HttpResponseReader.readFile** `http-response-reader-read-file` (`@venizia/ignis-helpers`, `@venizia/ignis`): `HttpResponseReader.readFile({ response })` answers `{ blob, filename?, contentType? }` for a download. It reads the filename from `Content-Disposition` (`filename*` first). A non-2xx answer throws the server's error, so you never save an error page as a file. Example: `HttpResponseReader.readFile({ response: await dataSource.request({ paths }) })`.
- **Client-context header names in HTTP.Headers** `http-headers-client-context` (`@venizia/ignis-helpers`, `@venizia/ignis`): `HTTP.Headers` now names `AUTH_PROVIDER` (`x-auth-provider`), `LOCALE` (`x-locale`), `TIMEZONE` (`timezone`) and `TIMEZONE_OFFSET` (`timezone-offset`). A client and a server can share one spelling of the headers that carry a credential's provider, the user's locale and their time zone.
- **Trusted origins for the url guard** `url-safety-trusted-origins` (`@venizia/ignis-helpers`): `policy.hosts: { trusted, strict? }` names the origins you trust. A trusted origin is reached even when it resolves to a private address, and the connection is pinned to the addresses that were checked. Trust is entered only through a trusted hop: once a redirect chain passes through an untrusted hop, a later trusted private origin gets the full guard, so a public url cannot redirect into an internal service. `strict: true` refuses every origin that is not listed. An entry that is not exactly an origin as `new URL(entry).origin` writes it throws a configuration error.
- **UrlFetchError** `fetch-guarded-typed-error` (`@venizia/ignis-helpers`): `NativeFetcher` and `AxiosFetcher` raise it when `acceptStatus` refuses a status (a 4xx or 5xx by default) and when a redirect may not be followed. It carries `status`, `url`, `headers`, `response` (the first 64 KiB of the body, still readable) and, for a redirect, `location`. `UrlFetchError.is(error)` narrows the type.
- **maxRedirects: 0 returns the 3xx** `fetch-guarded-no-redirects` (`@venizia/ignis-helpers`): a call with `maxRedirects: 0` raises a `UrlFetchError` with the first 3xx status and its `Location`, instead of "Too many redirects". A `Location` that is not a url raises the same error, not a bare `TypeError`.
- **A call takes a signal** `fetch-guarded-signal` (`@venizia/ignis-helpers`): pass `signal` on a call and it joins the call's one deadline, on both fetchers. If the caller aborts, the call rejects with the caller's own reason. If the deadline passes, it rejects with a `TimeoutError`.
- **Binding keys that carry their value type** `typed-binding-keys` (`@venizia/ignis-inversion`, `@venizia/ignis-kernel`, `@venizia/ignis`): `BindingKeys.build<T>({ namespace?, key })` makes a `TBindingKey<T>`, and `bind`, `get`, `getBinding`, `gets` and `Binding.bind` read `T` from it. `container.get({ key })` is typed with no generic, and a wrong value does not compile. A plain string or symbol still works and gives `unknown`. The key is the same plain string at run time, and `namespace` is now optional. `TBindingKeyValue<typeof key>` names the type, for a parameter annotation.
- **The framework's keys are typed** `typed-framework-keys` (`@venizia/ignis-kernel`, `@venizia/ignis`): every key of the API reference, gRPC, health check, server info, Socket.IO, static asset, WebSocket, authenticate, authorize and REST components now carries its value type, under the same key string. `AuthorizeBindingKeys.enforcerOptions<T>(name)` and `StaticAssetBindingKeys.policyService` / `commitService` return typed keys.
- **devz codemod binding-keys** `binding-keys-codemod` (`@venizia/dev-configs`): rewrites raw binding keys to `BindingKeys.build<T>({ key })` in your project's TypeScript sources (`--write`, `--check`, `--import-from`). A key your app keeps in a constant is built where it is declared, even in another file. A key written `Foo.name` or `this.constructor.name` is wrapped in place. An anonymous class whose `.name` is `''` now throws at that call, because `BindingKeys.build` refuses an empty key. It cannot be reversed: to downgrade, restore the files from git.
- **The framework's remaining keys are typed** `typed-core-and-mail-keys` (`@venizia/ignis-kernel`, `@venizia/ignis`): `CoreBindings` and the mail component's `MailKeys` carry their value types under the same strings.
- **A zod schema on every call** `fetcher-schema` (`@venizia/ignis-helpers`): a body that does not fit the schema throws `FetchSchemaError` (502, `core.fetch.schema_mismatch`). The error names the paths and rules, never the body.
- **Retry on every call** `fetcher-retry` (`@venizia/ignis-helpers`): set `retry` on a call or in `defaults` to retry a network error, a timeout, a 5xx and a 429. A guard refusal or a schema mismatch is never retried. It honours `Retry-After` up to `backoff.maxDelayMs` (a longer ask ends the retries) and keeps a `maxTotalMs` budget. A body that can be sent only once (a stream, or a `FormData` on `AxiosFetcher`) cannot be retried. A guarded call caps the body at 10 MiB unless `maxBytes` says otherwise. `RetryUtility.executeWithRetry` takes a `getDelayMs` floor.
- **Fetcher defaults and hooks** `fetcher-defaults-hooks` (`@venizia/ignis-helpers`): the constructor takes `defaults` (`timeout`, `headers`, `retry`, `maxBytes`, `guard`) and `hooks` (`onRequest` before every attempt, `onResponse`, and `onError` once with the final error).
- **A guard on any fetcher call** `fetcher-guard-per-call` (`@venizia/ignis-helpers`): pass `guard`, `maxBytes`, `maxRedirects` and `signal` on a call. Both fetchers pin the connection to the vetted address (Axios through a per-call agent, tested over real TLS).
- **Sign a service call with one hook** `service-assertion-request-hook` (`@venizia/ignis`): `signer.createRequestHook({ audience })` signs the method and the percent-encoded path before every attempt, retries included, and sets the assertion header. `Authorization` is untouched.
- **Two HTTP constants** `http-constants-json-utf8-real-ip` (`@venizia/ignis-helpers`): `HTTP.HeaderValues.APPLICATION_JSON_UTF8` (`application/json; charset=utf-8`) and `HTTP.Headers.X_REAL_IP`. The framework's own clients and middlewares read header names and values from `HTTP` instead of writing them out.
- **acceptStatus takes a list** `fetcher-accept-status-list` (`@venizia/ignis-helpers`): `acceptStatus: [HTTP.ResultCodes.RS_4.NotFound]` adds the listed statuses to 2xx. The function form still decides alone, and an empty list means 2xx only.
- **modes.allow limits the modes a search route takes** `search-modes-allow` (`@venizia/ignis-connectors`, `@venizia/ignis`): `SearchControllerFactory.build({ modes: { allow: [SearchModes.KEYWORD] } })` serves only the listed modes (`keyword`, `semantic`, `hybrid`; all three when left out). The body schema and the OpenAPI document are built from the list, so any other `mode` is a `400` from the validator. An empty list, a duplicate or an unknown name throws when the controller is built.
- **A refused answer keeps its body** `fetch-error-body-kept` (`@venizia/ignis-helpers`): `UrlFetchError.response` carries the first 64 KiB of the body, still readable (`await error.response.json()`), so you can read the reason the upstream gave. The rest is cancelled and the socket is freed.
- **NativeFetcher takes a fetch sender** `native-fetcher-sender` (`@venizia/ignis-helpers`): `new NativeFetcher({ fetch })` sends through your function (a test double, a proxy, an instrumented client). Without it, the global `fetch` is read at call time.
- **shouldRetry may be async, and a standard FormData can be retried** `retry-async-should-retry` (`@venizia/ignis-helpers`): `RetryUtility.executeWithRetry` and the fetchers' `retry.shouldRetry` may return a promise. A `FormData` body is encoded again on each send, so `NativeFetcher` can retry it.
- **One reader turns a Response into text** `response-reader-text` (`@venizia/ignis-helpers`): `HttpResponseReader.readText({ response, maxBytes? })` answers `''` for a 204, an empty body or no body, and fails at the cap. The fetchers' schema path uses it too, so a client of the IGNIS contract and a fetcher agree on an empty body.
- **HttpResponseReader.fromFetchError** `http-response-reader-from-fetch-error` (`@venizia/ignis-helpers`, `@venizia/ignis`): works like `toApplicationError`, but takes the `UrlFetchError` instead of a response. It reads the body the `UrlFetchError` kept.
- **The server's own text as the error message** `http-response-reader-message-from` (`@venizia/ignis-helpers`, `@venizia/ignis`): call `HttpResponseReader.toApplicationError` or `fromFetchError` with no `context` and `message` is the server's text alone (`HTTP <status>` when it sent none), instead of `context | server text`. Use it when a client shows `message` to users. With a `context`, the message is unchanged.
- **UrlBuilder** `url-builder` (`@venizia/ignis-helpers`, `@venizia/ignis`): `UrlBuilder.join({ baseUrl, paths, scope, origin? })` is the one strict join of a base and path segments. `HttpDataSource` uses it too, with the same refusals it always had. A double slash is not refused, and a `?` inside a segment still starts the query.
- **Sections in mail templates** `mail-template-sections` (`@venizia/ignis`): <code v-pre>{{#list}}...{{/list}}</code> repeats a block per item (<code v-pre>{{.}}</code> is the item; its keys resolve against the item, then the outer data). <code v-pre>{{#flag}}...{{/flag}}</code> renders when the value is truthy, and <code v-pre>{{^flag}}...{{/flag}}</code> when it is absent, false, empty or an empty list. The renderer is IGNIS's own: own properties only, no partials, no lambdas, no delimiter change, no code. A malformed template, an unsupported tag or sections nested deeper than 64 throw `core.mail.template_invalid`. A render that leaves values empty logs one warning listing the keys (never the values). `validateTemplateData` reports the section keys (never as missing).
- **missing option** `mail-template-missing-option` (`@venizia/ignis`): `render()` and `sendTemplate()` take `missing: 'empty' | 'keep' | 'throw'`. `requireValidate` still lists every missing key first.
- **importDocuments takes the remote-embedding and return options** `typesense-import-options` (`@venizia/ignis-connectors`, `@venizia/ignis`): `TypesenseConnector.importDocuments` gains `remoteEmbedding: { batchSize, timeoutMs, numTries }` (sent as `remote_embedding_batch_size`, `remote_embedding_timeout_ms` and `remote_embedding_num_tries`), `returnId` and `returnDoc` (`return_id`, `return_doc`; each row of `responses` then carries the `id` and the `document`). Each number is a positive integer, and a bad value is refused before anything is sent. This is Typesense-only. A collection embedded by a remote provider no longer has to bypass the connector to import. A call that passes none of them sends what it always did.
- **BullMQHelper stamps job metadata** `bullmq-job-metadata` (`@venizia/ignis-helpers`, `@venizia/ignis`): `new BullMQHelper({ metadata: () => ({ requestId }) })` stamps a block on every job added through the new `add({ name, data, opts? })`. The block is stored in the job's `opts.metadata`, never in `job.data`, so a processor that parses `data` strictly, and any raw `Worker`, `QueueEvents` or dashboard, sees the payload as added. `onWorkerData(job, { metadata })` and `BullMQHelper.readMetadata({ job })` read it; a job added without a stamp has none. A throwing stamp fails the add, and an `opts.metadata` set by the caller is refused. `BullMQHelper` has a third type argument for the metadata (defaulted, so existing code compiles). `queue.add` stays available and unstamped.
- **A key prefix for BullMQ queues** `bullmq-key-prefix` (`@venizia/ignis-helpers`, `@venizia/ignis`): set `prefix` on `BullMQHelper`, or on the mail executor's `queue` option, to set the Redis key prefix of the Queue and the Worker together. It is opt-in: unset stays BullMQ's `bull`, so no key moves. A developer machine can take a prefix of its own and never pick up shared DEV jobs. Changing the prefix of a queue that has data strands its keys: the queue helper docs list the steps to move one.
- **ConstClass for your own value classes** `const-class-added` (`@venizia/ignis-helpers`, `@venizia/ignis`): `class Modes extends ConstClass { static readonly READ = 'read'; }` gives `Modes.values()` (a non-empty tuple that `z.enum` takes as it is) and `Modes.isValid(value)`, which narrows to `TConstValue<typeof Modes>`. A class that extends another const class lists the inherited values too. `devz codemod const-classes` moves a class with the old `SCHEME_SET` and `isValid` shape onto it.

## Changed
- **Supported runtime: Bun 1.4 or newer** `bun-1-4-supported` (`@venizia/dev-configs`): `engines.bun` is now `>=1.4` (dev-configs asked for `>=1.4.4`; the other packages already said `>=1.4`). Bun 1.4.5 is recommended, but not required: it is a security release with TLS, HTTP and DNS fixes in `fetch`, `Bun.serve` and `node:tls`/`https`/`http`/`dns`.
- **An explicit generic that does not fit the key is a type error** `typed-key-claims` (`@venizia/ignis-inversion`, `@venizia/ignis-kernel`, `@venizia/ignis`): `container.get<T>({ key })` and `bind<T>({ key })` accept a `T` that is a subtype or a supertype of the key's type, and refuse an unrelated one. Before, that compiled and failed at run time. Only a call that claims a type unrelated to a typed key is affected; strings and run-time behaviour do not change. `@inject({ key })` is not checked against the decorated parameter: annotate it with `TBindingKeyValue<typeof key>`.
- **A search controller without modes.raw no longer lists raw in its OpenAPI document** `search-raw-dropped-from-schema` (`@venizia/ignis-connectors`, `@venizia/ignis`): `mode: 'raw'` is left out of the body schema until you set `modes.raw: { use: true }`. A raw request still gets a `400`, now from the validator and its message instead of the run-time one.
- **HttpDataSource sends through NativeFetcher** `http-datasource-on-native-fetcher` (`@venizia/ignis-connectors`, `@venizia/ignis`): the data source no longer carries its own send and 401-retry code. `onUnauthorized` gets the `attempt` as a second argument, `onUnauthorized(context, { attempt })`, and is also called on the retry's own 401 (its answer is ignored, the 401 stands, and nothing is sent a third time), so an app can log out when a refresh did not work. Three things differ for a caller. A call aborted while the session refreshes (or when the hook hears the second 401) now rejects with the caller's abort reason, where it used to resolve with the 401 error. `request()` with a `GET` or `HEAD` that carries a body fails with an `ApplicationError` that names the url, where the platform threw a `TypeError`. A custom `settings.fetch` is called with the url as text and an `init` that also names `redirect: 'follow'` and may carry a composed signal. The headers, token, `x-request-count` and error-reading rules are unchanged, and the `context` object is still the same one for the token resolver, the headers resolver and `onUnauthorized` within one call, on every send. `connectors/http` is about 63 KB minified, 35 KB more than before, because the fetcher pipeline ships with it.
- **An empty body under maxBytes with a schema is a FetchSchemaError** `fetch-empty-capped-schema` (`@venizia/ignis-helpers`): this case used to fail with "Response carried no body" when the call set `maxBytes`, and with a `FetchSchemaError` when it did not. Now both give a `FetchSchemaError`.
- **One message for a body over the cap** `body-cap-one-refusal` (`@venizia/ignis-helpers`): `BodyLimit`, the fetchers and the Axios size error all refuse with `[fetch] Body exceeds the cap | ...` and the url-refused code. The text used to begin `[capStream]` or `[readBytes]`. If you matched on those prefixes, match on `Body exceeds the cap`.

## Fixed
- **A guarded call on AxiosNetworkRequest built with baseUrl says what to do** `axios-guard-base-url-message` (`@venizia/ignis-helpers`): the refusal now reads "a guarded call needs one absolute url: use an AxiosFetcher without baseUrl, or a NativeFetcher". It used to name `baseURL`, an option you never wrote.
- **fromFetchError no longer throws on a status outside 200-599** `from-fetch-error-status-range` (`@venizia/ignis-kernel`): a hand-built `UrlFetchError` with status 0 is answered as a bad gateway (`502`) instead of a `RangeError`.

## Security
- **A metadata address opens only by its own literal** `trusted-origin-metadata` (`@venizia/ignis-helpers`): `169.254.169.254` and its kin (`100.100.100.200`, `fd00:ec2::254`, link-local, and their IPv4-mapped, NAT64 and 6to4 spellings) are reached only when the trusted origin's host is that exact IP and the chain was trusted from the first url. A trusted host name that resolves to one, or a redirect from an untrusted hop to one, is refused.
- **A url with credentials is refused on a trusted origin too** `trusted-origin-credentials` (`@venizia/ignis-helpers`): `http://user:password@vault/` has a trusted origin but is still refused. Send credentials in a header.
