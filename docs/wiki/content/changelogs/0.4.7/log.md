IGNIS 0.4.7 moves 184 public functions onto classes and removes their old bare names, adds one logger factory that also runs in a browser, makes AES and RSA async, puts Hash on Bun, and removes the connector sub-paths of `@venizia/ignis`, MinIO support, `LegacyAES`, the `Envs` alias and a set of unused exports. It adds `CredentialHelper`, search count, facets and suggest, a streaming Typesense export, opt-in async-style lint rules, and the `devz codemod` commands `namespace-functions` and `connector-imports`, which rewrite your calls and imports. An app on 0.4.6 that uses a renamed, moved or removed name does not compile until it runs the codemods and fixes by hand what they only list. `@venizia/ignis-inversion` and `@venizia/ignis-filter` are released with this line as 0.4.6, and their changes are listed here.

## Breaking

- **Old function names are removed** `old-function-names-removed` (`@venizia/ignis-inversion`, `@venizia/ignis-filter`, `@venizia/ignis-helpers`, `@venizia/ignis-boot`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis-worker`, `@venizia/ignis`, `@venizia/dev-configs`): 184 public functions are now static methods on classes, with no aliases, such as `isEmpty` to `ObjectUtility.isEmpty`, `uuidV4` to `UuidV4Generator.generate`, `jsonResponse` to `OpenApiResponses.jsonResponse` and `defineAuthController` to `AuthControllerFactory.define`. 39 of them took positional arguments and now take one options object (`sleep(ms)` is `PromiseUtility.sleep({ ms })`). `isMailTransport` and `isValidMailOptions` are `MailTypeUtility.isTransport` and `MailTypeUtility.isValidOptions`. Error and log message tags that began with a function name now begin with the class and method (`[toEntityId]` is `[ModelUtility.toEntityId]`), so tests and alerts that match the text stop matching. Run `devz codemod namespace-functions`, then fix what it lists.
- **The logger types are removed** `logger-types-removed` (`@venizia/ignis-helpers`, `@venizia/ignis`): `ApplicationLogger`, `LoggerResolver`, `TLoggerResolver` and `SHOULD_LOG_DEBUG` are gone. Get a logger with `LoggerFactory.getLogger([scope])`, choose the provider and level with `LoggerFactory.use({ provider, level })`, and read the debug gate with `LoggerDebugGate.isOpen()`. `ConsoleLogger.get` takes the scope as a string, `ConsoleLogger.get('x')`, and returns a `ConsoleLogger`. The namespace codemod moves `ApplicationLogger.get(...)`; your typecheck finds a `LoggerResolver.use({ resolver })` and a `ConsoleLogger.get({ scope })`.
- **MinIO support is removed** `minio-removed` (`@venizia/ignis-helpers`, `@venizia/ignis`): `MinioHelper`, `IMinioHelperOptions`, the `@venizia/ignis-helpers/minio` sub-path, the `minio` optional peer and `StaticAssetStorageTypes.MINIO` are gone. Use `BunS3Helper` from `@venizia/ignis-helpers/bun-s3` against your MinIO server's S3 API, and `StaticAssetStorageTypes.BUN_S3` for the static-asset `storage` option.
- **`readAffectedRowCount` is removed** `read-affected-row-count-removed` (`@venizia/ignis`): it had no replacement. Read `rows.length` from a statement that returns rows, or read the affected count from your driver's raw result.
- **AES and RSA are async** `aes-rsa-async` (`@venizia/ignis-helpers`, `@venizia/ignis`): `AES` and `RSA` run over Web Crypto, and `encrypt`, `decrypt`, `encryptFile`, `decryptFile`, `RSA.generateDERKeyPair` and `normalizeSecretKey` return promises. `encryptPayload` and `decryptPayload` of the bearer token services return promises too. Add `await`, and update your own overrides and subclasses of `BaseCryptoAlgorithm`. Input checks are stricter (a key that is not 32 bytes, an IV that is not 16 bytes, a GCM tag that is not 16 bytes, a `kdfIterations` outside 1 to 2147483647 are refused), and a failed decryption rejects with `OperationError: The operation failed for an operation-specific reason`. Stored data still decrypts: the output bytes are unchanged.
- **`LegacyAES` and the `cipher` option are removed** `legacy-aes-removed` (`@venizia/ignis-helpers`, `@venizia/ignis-kernel`, `@venizia/ignis`): `LegacyAES`, `IPayloadCipher`, `DEFAULT_PAD_END` and the `cipher` option of `IJWSTokenServiceOptions`, `IJWKSIssuerOptions` and `IJWKSVerifierOptions` are gone, so data written in the format before the PBKDF2 envelope has no reader. Decrypt it with `LegacyAES` and write it back with `AES` before you update, and remove `cipher` from your token services. Sessions issued under the old envelope end.
- **The `Envs` alias is removed** `envs-alias-removed` (`@venizia/ignis-helpers`): use `applicationEnvironment` (or `AppEnvs`), which is the same object.
- **The connector sub-paths of `@venizia/ignis` are removed** `connector-subpaths-removed` (`@venizia/ignis`, `@venizia/ignis-connectors`): 13 sub-paths (`/postgres`, `/postgres/node-postgres`, `/postgres/postgres-js`, `/postgres/pglite`, `/postgres/supabase`, `/relational`, `/sqlite`, `/sqlite/libsql`, `/search`, `/search/controllers`, `/meilisearch`, `/typesense`, `/typesense/controllers`) no longer exist, and `@venizia/ignis` no longer declares `pg`, `postgres`, `@electric-sql/pglite`, `@libsql/client`, `meilisearch` and `typesense` as optional peers. Import from the same sub-path of `@venizia/ignis-connectors`, list that package and the driver you use in your own dependencies, and run `devz codemod connector-imports`. The root of `@venizia/ignis` still re-exports the Postgres connector.
- **Exports nothing used are removed** `unused-exports-removed` (`@venizia/ignis-inversion`, `@venizia/ignis-filter`, `@venizia/ignis-kernel`, `@venizia/ignis-connectors`, `@venizia/ignis`, `@venizia/dev-configs`): `TApplicationError`, `TLimit`, `TOffset`, `TSkip`, `TOrderBy`, `TQueryOperator`, `TQuerySchemas`, the `App` constants class, `isSqliteTransaction`, `IInjectMetadata` and `IPropertyMetadata` (from the kernel and `@venizia/ignis`; import them from `@venizia/ignis-inversion`), `ReactEslintConfigs` and `IReactEslintPlugins`, and the `ts-node` block of `tsconfig.common.json`. Each has a replacement in the migration block.
- **The old `@model` keys are ignored and `devz codemod model-settings` is removed** `model-settings-keys-removed` (`@venizia/ignis-kernel`, `@venizia/ignis`, `@venizia/dev-configs`): `@model` no longer throws for `defaultFilter`, `defaultLimit`, `maxLimit`, `scopeFilter` or `skipMigrate`. A typed model fails the typecheck; an untyped one has the key ignored, and a lost `scopeFilter` means no row scope. The new keys are `settings.query.filter`, `settings.query.limit.default`, `settings.query.limit.max`, `settings.access` and `migration: { use: false }`.
- **`roles` is optional on the JWT payload** `jwt-roles-optional` (`@venizia/ignis-kernel`, `@venizia/ignis`): `IJWTTokenPayload.roles` is `roles?: TJWTTokenRole[]`, so code that reads `roles` without a check fails the typecheck. The new `TJWTTokenRole` (`{ id, identifier, priority }`) names the role shape. Nothing changes at run time.
- **`Hash` and the commit token need Bun** `hash-needs-bun` (`@venizia/ignis-helpers`, `@venizia/ignis`): `Hash.digest`, `Hash.hmac` and `AssetCommitToken` compute with `Bun.CryptoHasher` and throw `ReferenceError: Bun is not defined` under Node, in a Vite config or in a browser bundle. Output for the same input is unchanged, so stored digests and handed-out tokens still verify. Move that code to Bun, or use `crypto.subtle` there.
- **A search engine 4xx is thrown as a 4xx** `search-engine-4xx-status` (`@venizia/ignis-connectors`, `@venizia/ignis`): when Typesense or Meilisearch answers 400, 404, 409 or 422, the connector throws that status with the engine's message (`404 core.search_engine.not_found`, `409 core.search_engine.already_exists`) where it threw `503 core.search_engine.dependency_unavailable`. Transport failures, 5xx, 401, 403, 408 and 429 stay a 503. Retry code and alerts that matched the 503 for a rejected request now see the 4xx.
- **`facetCounts` is typed and camelCase, and hidden fields are refused** `search-facet-counts-shape` (`@venizia/ignis-connectors`, `@venizia/ignis`): `ISearchResult.facetCounts` is `ISearchFacetCount[]`. Typesense `field_name` and `stats.total_values` become `fieldName` and `stats.totalValues`, and Meilisearch gives one entry per field (`{ fieldName, counts: [{ value, count }] }`) where it gave one raw `facetDistribution` record. `search()`, `searchCount()`, `facets()` and `suggest()` also refuse, with a 400, a field the model hides in `facetBy`, `facetQuery`, `queryBy`, `groupBy` and the highlight fields; before, `facetBy` on a hidden field returned its value counts.
- **`ITypesenseClientLike` needs `exportStream`** `typesense-client-like-export-stream` (`@venizia/ignis-connectors`): the `documents()` of a client you pass to the connector must have `exportStream(options?)`, which resolves to an async iterable of text or bytes. The real `typesense` client already has it; a test fake or wrapper must add it.

## Added

- **One logger factory for the server, a script and a browser** `logger-factory-in-core` (`@venizia/ignis-helpers`, `@venizia/ignis`): `LoggerFactory` and `ConsoleLogger` are exported from `@venizia/ignis-helpers/core` and import nothing from node. `LoggerFactory.use({ provider, level })` sets the provider and a `LogLevels` level; the level overrides the `DEBUG` and `NODE_ENV` rule for every provider. The default provider is the console (it was Winston, which threw when it could not load), and `@venizia/ignis` selects Winston at `initialize()` when you chose nothing, so a compiled binary needs no logger setup. If Winston is installed but cannot load, one `[ServerLoggerStartup]` warning is printed and the console stays. `useUnlessChosen`, `isChosen`, `reset` and `LoggerDebugGate` are new. Lines logged before `initialize()` use the console format.
- **`CredentialHelper` hashes and checks passwords** `credential-helper` (`@venizia/ignis-helpers`): `CredentialHelper.hash({ password, algorithm?, cost? })` and `CredentialHelper.verify({ password, hash })` run on `Bun.password`. `hash` writes argon2id by default and bcrypt with `algorithm: 'bcrypt'`; `cost` (4 to 31, default 10) is for bcrypt only and throws with argon2id. `verify` reads bcrypt hashes from the `bcrypt` package (including the 72-byte retry) and argon2 hashes, and never rehashes. It needs Bun.
- **`Hash` takes bytes and several parts** `hash-bytes-and-parts` (`@venizia/ignis-helpers`): `Hash.hmac` takes `string | Uint8Array` for the message and the secret, and `Hash.digest` takes `string | Uint8Array` or an array of them, hashed in order as one message. Text input gives the same output as before.
- **`ECDH` runs in a browser** `ecdh-in-the-browser` (`@venizia/ignis-helpers`): `ECDH`, `AbstractCryptoAlgorithm` and the types `ECDHAlgorithmType`, `IECDHEncryptedPayload` and `IECDHExtraOptions` are exported from `@venizia/ignis-helpers/core`. `ECDH` no longer uses `Buffer`, and the wire format is unchanged, so a server and a browser read each other's payloads.
- **`RecursiveTreeSql.walk` takes several roots, no root and one filter** `recursive-tree-roots` (`@venizia/ignis-connectors`): `rootId` is `string | string[] | undefined`, a DOWN walk with no root starts from every row with a NULL parent, `filter` is ANDed into both terms (alias `t`), and `start: 'all'` makes every row a root. An UP walk with no root, an empty list, and `start` with `rootId` are refused. A call without the new options produces the SQL it did before.
- **The search repository counts, returns facets alone and suggests** `search-count-facets-suggest` (`@venizia/ignis-connectors`, `@venizia/ignis`): `searchCount({ query, queryBy?, where? })` answers `{ count, isFoundExact }`, `facets({ facetBy, ... })` answers `{ facets, found, isFoundExact }` with no hits, and `suggest({ query, ... })` answers matching documents for a search box. All three take `engineParams`, checked like `search()`. Typesense tuning has typed camelCase names in `ITypesenseTuning` (including `maxCandidates`), `highlight: false` turns off highlight markup on a keyword search, and a hybrid hit carries `rankFusionScore` and `vectorDistance`.
- **The Typesense connector streams exports** `typesense-streaming-export` (`@venizia/ignis-connectors`, `@venizia/ignis`): `streamDocuments` yields an export as NDJSON lines with bounded memory, `exportDocuments` and `streamDocuments` take `excludeFields`, and `exportDocuments`, `streamDocuments`, `importDocuments`, `getCollection`, `createCollection` and `patchCollectionSchema` take `timeoutMs`. A connector built with your own `client` also needs `createClient({ connectionTimeoutSeconds })` for a call that sets `timeoutMs`.
- **`TypesenseConnector.findDocument`** `typesense-find-document` (`@venizia/ignis-connectors`, `@venizia/ignis`): returns the document or `null` for a missing document or collection; `document.find` is the same call, and `getDocument` still throws a 404.
- **`importDocuments` can throw on a partial import** `typesense-import-throw-on-fail` (`@venizia/ignis-connectors`, `@venizia/ignis`): `throwOnFail: true` throws a 422 after the last batch, with the counts in `extra.details` and the per-row responses on `error.responses`. The default is unchanged: rejected rows come back in `count.fail` and `responses`.
- **The transaction doubles take a connector and commit hooks** `transaction-doubles-connector` (`@venizia/ignis-connectors`, `@venizia/ignis`): `TransactionDouble`, `PostgresTransactionDouble` and `SqliteTransactionDouble` take an optional `connector`, `onCommit` and `onRollback`, and are generic over the connector type. Code that already uses them compiles unchanged.
- **Async-style lint rules and a codemod** `async-style-rules` (`@venizia/dev-configs`): `venizia/no-inline-await` and `venizia/no-return-await` (in `asyncStyleConfigs`), and `venizia/no-async-hook-callback` and `venizia/effect-cleanup-consistency` (in `reactAsyncStyleConfigs`), are off until you spread those arrays. `devz codemod async-style` applies the two await fixes, gives each hoisted const a name that is unique in its function, leaves a file alone and lists it when the rewrite would be worse, and lists what it cannot fix.
- **Lint rules for awaited promise chains and silent catches** `await-chain-and-silent-catch-rules` (`@venizia/dev-configs`): `venizia/no-await-promise-chain` reports an `await` of a `.then`, `.catch` or `.finally` chain, and `venizia/no-silent-catch` reports a catch that swallows an error. Both are in `asyncStyleConfigs` and `reactAsyncStyleConfigs`, and `devz codemod async-style` fixes the `const x = await f().catch(() => value)` shape.
- **`devz codemod namespace-functions`** `namespace-functions-codemod` (`@venizia/dev-configs`): rewrites imports and calls of the removed function names and `ApplicationLogger.get(...)`, follows named, aliased and namespace imports, is a dry run unless `--write`, refuses a file with local changes, and lists what it cannot rewrite (a spread argument, an old name used as a value, a re-export, a name collision, an `@/` alias).
- **`devz codemod connector-imports`** `connector-imports-codemod` (`@venizia/dev-configs`): rewrites the 13 removed `@venizia/ignis` sub-path specifiers in an import, an export from, a dynamic `import()`, a `require()`, an `import()` type and a `mock.module()` call in `.ts`, `.tsx`, `.mts` and `.cts` files. It is a dry run unless `--write`, `--check` exits 1 while a file would change, and it names each `package.json` that does not list `@venizia/ignis-connectors`.
- **A `shared` kind in the IGNIS preset** `shared-preset-kind` (`@venizia/ignis`): with a VULCAN that has `--shared`, `vulcan add --preset ignis --shared common` makes a side-neutral package with no framework dependency, so a backend and a frontend can both import it. The `lib` kind is unchanged.

## Changed

- **`devz codemod --write` needs a path or `--all`** `codemod-write-needs-path` (`@venizia/dev-configs`): `async-style`, `const-classes` and `drop-redundant-casts` exit 2 and write nothing for `--write` with no path. Pass a path, or `--all` for the whole working tree. A dry run and `--check` are unchanged.
- **`devz codemod const-classes` writes no comment** `const-classes-codemod-no-comment` (`@venizia/dev-configs`): it no longer writes a `/** The values of ... */` comment above each class it creates. Names, members, `SCHEME_SET` and `isValid` are the same.
- **The mail generators name bad input** `mail-generators-validate-input` (`@venizia/ignis`): `NumericCodeGenerator.generateCode(length)` throws for a length whose `10 ** length` is not an integer from 1 to 281474976710656, and `RandomTokenGenerator.generateToken(bytes)` throws for a size that is not a non-negative integer. Both draw from `crypto.getRandomValues`.
- **`updateByFilter` refuses an empty `document`** `typesense-update-by-filter-empty` (`@venizia/ignis-connectors`): `TypesenseConnector.updateByFilter` throws a 400 `[updateByFilter] Empty document` before it calls the engine.
- **`password` is optional on `RedisSingleHelper`** `redis-single-password-optional` (`@venizia/ignis-helpers`, `@venizia/ignis`): leave `password` out of `IRedisSingleHelperProps` when your Redis has none; cluster and sentinel already did. Nothing changes at run time.
- **The preset templates are updated** `preset-templates-updated` (`@venizia/ignis`): the app preset's Dockerfile builds on `oven/bun:1.4.4-alpine`, its `hello.controller.ts` and `boot.test.ts` use the class forms (`OpenApiResponses.jsonContent`, `ApplicationBootAssertion.assert({ application })`), and the `lib` summary text changed. A project made earlier edits its own copy, and the namespace codemod rewrites the calls.
- **The artifact scan cache rescans once** `artifact-scan-cache-hash` (`@venizia/ignis-boot`): the cache file name and tree fingerprint come from a pure hash that gives the same text under Node and Bun, so the first build after the update scans again and writes a new entry.
