# Changelog - 2026-09-06

## Two small fixes in helpers and boot

<Badge type="warning" text="Behavior Change" />

**In one line.** Installing `@venizia/ignis-helpers` outside a workspace now tells you about `@hono/zod-openapi` up front, and a generated artifact index tells you the exact command that regenerates it.

## What changed

- **`@hono/zod-openapi` is a declared peer of helpers** (`"@hono/zod-openapi": "^1.5.1"`, the same floor `@venizia/ignis-kernel` declares). The helpers root barrel loads it at import time, but it was only a `devDependency`, so an install into an empty directory failed on the first import.
- **The generated index header prints the real command.** It used to always read `Regenerate: ignis-artifacts generate --root src --out src/generated/artifacts.ts`. It now includes the `--root`, `--out`, `--ignore` and `--export` you used. `--ignore` appears when the list is non-empty; `--export` appears when the name is not `GeneratedArtifacts`.
- **`ArtifactIndexEmitter` API.** `render()` takes a required `command: { root, out, ignore? }`, `renderHeader()` is public, and `HEADER` is removed.

```typescript
// AUTO-GENERATED by @venizia/ignis-boot - do not edit. Regenerate: ignis-artifacts generate --root src --out src/_artifacts.ts --ignore controllers/**
```

## Who is affected

- **Apps on `@venizia/ignis` or `@venizia/ignis-kernel`.** They already have the peer; no change.
- **Projects that import the helpers root barrel alone, outside a workspace.** Install `@hono/zod-openapi` once; the install warning names it.
- **Every generated index.** Its first line changes, so `ignis-artifacts check` reports it stale once. A build that runs `generate` before `check` heals itself; otherwise run `generate` once after upgrading.
