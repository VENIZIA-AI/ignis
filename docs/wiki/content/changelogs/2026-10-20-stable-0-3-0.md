# Changelog - 2026-10-20

## IGNIS 0.3.0 Is Stable, and One Command Creates an IGNIS App

<Badge type="tip" text="New Feature" /> <Badge type="tip" text="Enhancement" />

**In one line.** Every IGNIS package moves to 0.3.0 on the `latest` tag, and `@venizia/ignis` ships a VULCAN preset to create a working IGNIS app with one command.

```bash
bun x @venizia/vulcan init --preset ignis
```

## What changed

- **Every IGNIS package moves to 0.3.0 on the `latest` tag.** `@venizia/ignis-boot` moves from 0.2.1, while `@venizia/dev-configs` stays 0.3.1.

| Package | Version |
|---------|---------|
| `@venizia/ignis`, `@venizia/ignis-worker` | 0.3.0 |
| `@venizia/ignis-kernel`, `@venizia/ignis-connectors` | 0.3.0 |
| `@venizia/ignis-helpers`, `@venizia/ignis-inversion`, `@venizia/ignis-filter` | 0.3.0 |
| `@venizia/ignis-boot` | 0.3.0 |
| `@venizia/dev-configs` | 0.3.1 |

- **No runtime API changed from 0.2.2.** The minor moves so the whole line, and the frontend framework that builds on it, share one minor version.
- **`@venizia/ignis` ships a VULCAN preset.** `bun x @venizia/vulcan init --preset ignis` creates a monorepo with a working IGNIS app (one controller, AutoArtifacts, the API reference, a smoke test), installs it and runs its checks. Link: [5-Minute Quickstart](/guides/get-started/5-minute-quickstart). Requires VULCAN 0.3.0 or later.
- **The preset always names the release it ships in.** The preset's versions are written by the release.
- **Siblings stay pinned exactly to each other.**

## Who is affected

- **An application on 0.2.2.** Move every `@venizia/ignis-*` package to 0.3.0 in one change, no code change needed.
- **A library that peers on IGNIS with `^0.2.2`.** A `0.x` caret does not cross a minor, so move the peer range to `^0.3.0` together with the application.
- **A new project.** Use the one command.
