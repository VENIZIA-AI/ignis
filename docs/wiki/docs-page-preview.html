Repositories

Repositories are the data-access layer. They wrap a Drizzle table behind a typed, options-object API - queries, relations, transactions and soft-delete - so your services never touch raw SQL.

💡 Tip

A repository auto-injects its DataSource from the @repository decorator. No constructor needed for the common case.

The repository hierarchy

Every repository composes up a four-level chain, each adding capability. Pick the one matching what the model needs:

  • AbstractRepository - entity & metadata resolution
  • ReadableRepository - find, findById, findOne, count
  • PersistableRepository - create, updateById, deleteById
  • DefaultCRUDRepository - everything above, the usual choice
user.repository.ts⧉ Copy
import { repository, DefaultCRUDRepository } from '@venizia/ignis'
import { User } from '../models'
import { PostgresDataSource } from '../datasources'

@repository({ model: User, dataSource: PostgresDataSource })
export class UserRepository extends DefaultCRUDRepository<typeof User.schema> {}

Querying with filters

All read methods take a single options object with a filter. The filter carries where, order (an array of "field DIR" strings), include for relations, plus limit and offset.

user.service.ts⧉ Copy
const result = await this.userRepo.find({
  filter: {
    where: { status: 'active', age: { gte: 18 } },
    order: ['createdAt DESC'],
    include: [{ relation: 'profile' }],
    limit: 20,
  },
})  // → User[] with profile joined
⚠ Warning

create() returns { count, data }, not the bare row. Destructure data to get the inserted record(s).

Core methods

MethodSignatureReturns
findfind({ filter })T[]
findByIdfindById({ id })T
findOnefindOne({ filter })T | null
