# RPC client app

A React client for the IGNIS [`rpc-api-server`](../rpc-api-server). Its hooks are typed from the
server's OpenAPI document: `$api.useQuery("get", "/configurations")` knows the path, the body and
the reply, and a renamed route fails the build.

Start the server first (see its README), then:

```bash
bun install
bun run server:dev
```

Open `http://localhost:5173`. Sign up, then add and delete configurations. The Vite dev server
forwards `/api` to `http://localhost:3000`, so the server needs no CORS.

## What it shows

| File | What it does |
|---|---|
| `src/api/schema.d.ts` | Generated by `openapi-typescript` - do not edit |
| `src/api/client.ts` | `openapi-fetch` client that adds the Bearer token, wrapped by `openapi-react-query` into `$api` |
| `src/auth-form.tsx` | Sign up and sign in with `$api.useMutation` |
| `src/configurations.tsx` | List, create and delete with `$api.useQuery` / `$api.useMutation` |
| `src/app.tsx` | Keeps the token in `localStorage` and switches between the two |

## Regenerate the types

After a server change, with the server running:

```bash
bun run generate   # openapi-typescript http://localhost:3000/api/doc/openapi.json
bun run compile    # bun check, then vite build - fails where the client no longer matches
```

## Scripts

| Script | Does |
|---|---|
| `bun run server:dev` | Vite dev server on port 5173 |
| `bun run compile` | Typecheck, then bundle into `dist/` |
| `bun x vite preview` | Serve `dist/`, with the same `/api` forwarding |
| `bun run generate` | Rewrite `src/api/schema.d.ts` from the running server |
| `bun run typecheck` / `bun run lint` | `bun check` / `eslint .` |
