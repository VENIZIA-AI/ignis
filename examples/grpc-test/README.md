# grpc-test

An IGNIS application that answers the same kind of request over two transports: gRPC
([ConnectRPC](https://connectrpc.com)) and REST, registered side by side on one `Application`.

```bash
bun install
bun run start
```

The app listens on `http://localhost:3000` (set `PORT` to change it). Browse the REST API at
`http://localhost:3000/api/doc/explorer`.

## What it shows

| File | What it does |
|---|---|
| `src/controllers/greeter/proto/greeter.proto` | The one proto service, `GreeterService`, with its one RPC, `SayHello` |
| `src/controllers/greeter/generated/greeter_pb.ts` | Generated by `buf` - committed, regenerate with `bun run proto:gen` |
| `src/controllers/greeter/controller.ts` | `@controller({ transport: ControllerTransports.GRPC, service })` plus `@unary` on the handler |
| `src/controllers/status/controller.ts` | A plain REST controller, `GET /status` |
| `src/services/greeter.service.ts` | The business logic, injected into the gRPC controller |
| `src/application.ts` | Imports each decorated class; `discoverArtifacts: true` registers them |
| `src/index.ts` | Starts the server; `config.transports` turns REST and gRPC on together |

## Endpoints

Every route sits under `/api`. `config.transports: [ControllerTransports.REST, ControllerTransports.GRPC]`
in `src/index.ts` is what makes the gRPC branch exist at all - drop `GRPC` from that array and
`GreeterController` boots with a warning instead of a route.

| Transport | Method | Path | Does |
|---|---|---|---|
| REST | `GET` | `/health` | Liveness check |
| REST | `GET` | `/status` | App status and uptime |
| REST | `GET` | `/doc/openapi.json` | The OpenAPI document (REST routes only) |
| gRPC | `GreeterService.SayHello` | `/grpc/greeter.v1.GreeterService/SayHello` | Greets the caller by name |

## Call the gRPC method

ConnectRPC's Connect protocol speaks plain JSON over HTTP/1.1, so a unary RPC is one `curl` call
away - no gRPC client needed:

```bash
curl -s -X POST localhost:3000/api/grpc/greeter.v1.GreeterService/SayHello \
  -H 'content-type: application/json' -d '{"name":"Ignis"}'
# {"message":"Hello, Ignis!"}
```

A real client gets type-checked requests and responses from the same generated code:

```ts
import { create } from '@bufbuild/protobuf';
import { createClient } from '@connectrpc/connect';
import { createConnectTransport } from '@connectrpc/connect-web';
import { GreeterService, SayHelloRequestSchema } from './src/controllers/greeter/definition';

const transport = createConnectTransport({ baseUrl: 'http://localhost:3000/api/grpc' });
const client = createClient(GreeterService, transport);

const response = await client.sayHello(create(SayHelloRequestSchema, { name: 'Ignis' }));
console.log(response.message); // "Hello, Ignis!"
```

## Only unary RPCs

`BaseGrpcController` throws at boot, when it registers the route, for any RPC method that is not unary. The Connect
protocol runs on HTTP/1.1 here; server-streaming, client-streaming and bidirectional RPCs need
HTTP/2 (true gRPC), which this example does not set up. Keep new RPCs unary, or add HTTP/2 first.

## Test it

```bash
bun test
```

The smoke test boots the same `Application` on a free port, calls `GET /status` with `fetch` and
`GreeterService.SayHello` through a ConnectRPC client, and stops the app.

## Change the proto

Edit `src/controllers/greeter/proto/greeter.proto`, then regenerate:

```bash
bun run proto:gen
```

This runs `buf generate` against `src/controllers/greeter/proto/buf.gen.yaml`, which drives the
`protoc-gen-es` plugin into `src/controllers/greeter/generated/`. The generated file is committed -
`git diff` after regenerating shows exactly what the schema change produced. `src/controllers/greeter/definition.ts`
re-exports the generated names; controller code imports from there, never from `generated/` directly.

## Where the data goes

`bun run start` logs in `app_data/logs`. `app_data/` is gitignored.

| Variable | Default | Meaning |
|---|---|---|
| `APP_ENV_LOGGER_FOLDER_PATH` | `./app_data/logs`, set by the `start` script | Unset: console logging only |
| `PORT` | `3000` | The port the server listens on |
